## 1. 予約の印が相手からズレる（原因確認済み）
- 原因：キャラの絵は補間位置（main.ts 1127行付近 `this.interp.at(p.id, now)`、NET_INTERP_DELAY 0.25秒前の位置）で描いているのに、印はサーバーの最新座標（server/skills/bii.ts 42行 `e.v = marked(...).map(t => ({x, y, r}))`）で描いている。印が0.25秒ぶん先に行く（相手が歩いていると約40px）
- 直し方：サーバーは印の対象の thingId と r だけ送る。クライアントは対象の描画位置に印を描く。描画位置は、自キャラなら this.me、他キャラ・大将は interp.at（main.ts の描画と同じ取り方）
  - ENT_VIEW の draw は今 (g, e, time, color) で位置の引き方を持たないので、描画位置を引く関数を渡せるようにする
  - main.ts 1045行の thingPos も他キャラ・大将・コバコはスナップショット座標を返していて同じズレがある（照準の目印 mine.tgt で使用）。描画位置を返すように直し、印もこれを使ってよい
- 成功基準：歩いている相手・大将の頭上に印が遅れず付いている（目視、スクショか録画を添付）

## 1b. 爆発ポーズで見た目の位置が少し戻る（原因確認済み）
- 原因：自キャラは通常は予測位置（pred.render、サーバーより先）で描くが、lock の状態になると main.ts 1038行で `this.interp.at(mine.id, now)`（0.25秒前の補間位置）に切り替わる。オーバードライブ中は移動×1.6（約270px/秒）なので、ポーズ（overloadPose、lock）に入った瞬間に約70px後ろへ飛び、そこから0.25秒かけてポーズ位置へ進み直す。他人から見たビィは常に補間なので飛ばない（自分視点だけの問題）
- lock を補間で描くのは、サーバーが動かす状態（アルの rush、ひまりの leap）のため。その場で止まる lock（ビィの overloadPose、アルのタメ charge、そらの照射 solar）でも同じく後ろへ飛ぶ
- 直し方：状態に「その場で止まる lock」を示す印（例 `still: true`）を付け、スナップショットに載せる。自キャラが still の lock 中は補間に切り替えず、直前の表示位置からサーバーの最新位置（mine.x, y）へ NET_CORR_SPEED 程度でなめらかに寄せる。サーバーが動かす lock は今のまま補間
- 対象：overloadPose・charge・solar に still を付ける。他に止まる lock があれば同様に
- 成功基準：自分のビィでポーズ開始時に後ろへ飛ばない。アルのタメ・そらの照射開始でも飛ばない。アルの突撃・ひまりの跳躍の見た目は今と変わらない（自分視点の録画かスクショを添付）

## 2. 性能変更（移動技としての価値を下げ、さっさと爆発させる）

- 持続を短く：dur 3秒 → 仮1.5秒
- 加速（speed 1.6）・残像の間隔・ポーズ・ダメージ・CTは据え置き
- 説明文（desc）とキャラ一覧は数値が変わったら合わせる
- verify/server.ts の既存のオーバーロード検証を新しい値で通す。広い接触範囲で印が付くことの検証を追加
