# Code引き継ぎ：botai3（rush に対するメタのマクロがあるか）

2026-11-27 Chat作成。対象：~/kiritan_zunda_proto。前提は botai1・botai2 の報告（docs/botai_report.md・docs/botai2_report.md）。不明点は勝手に判断せず本人に確認。範囲外のコード・コメントは変えない。

## 本人の判断
- 問いは「rush に対するメタが成立するマクロがあるか」。無いならバランス調整が必要
- 今の farm は「資材集め」として機能しているか怪しい。資材拾いは、中立エリアでコバコが配る資材を除くと大して徳が得られない。敵陣に乗り込んで中くらいの資材を盗むくらいでないと差がつかない
- farm は「よわい Bot」として使えそうなことは分かった（farm はこのまま残す）

## 0. 徳の入り方の確認（実装の前に）
- 資材の種類ごと（自陣に湧く資材・敵陣の資材・コバコが中立に配る資材・高性能の徳 など、コードにある区分で）の1個あたりの徳と、botai1・botai2 のログでの1試合あたりの取得数・徳の合計を表にする
- 本人の見立て（自陣の資材は大して得られない、コバコの資材と敵陣の資材が大きい）とログが合っているかを書く
- 撤退中（反省中）の人数による徳の増え方（REFLECT_TOKU。n² で増える）もコードで確かめ、1人ずつばらばらに撤退した時と、4人そろって撤退した時の徳の差を計算して載せる

## 1. 作るマクロ（どれも「中」の操作、層は botai2 の u のみ付けてよい）
1. **steal（盗み）**：資材役は、自陣の資材ではなく、中立エリアのコバコの資材と、敵陣の中くらいの資材を優先して取りに行く。残りの役は std と同じ
2. **counter（迎撃→逆襲）**：開始時は全員で自陣の大将のそばに構える（守りの動きは botai2 で直した「大将から 300 以内の敵を迎え撃つ」）。敵が2人以上撤退中になったら、全員で敵の大将へ攻める。**攻め返したら途中で戻らない**：数的有利はすぐ解消されるので、敵が復帰しても構えに戻らず、そのまま rush と同じく攻め続ける。味方が全員撤退中になったら（全滅したら）、復帰後に構えへ戻る
3. **split（入れ違い）**：2人は counter の構え、2人は rush と同じく攻める

4. **層 w（一斉撤退）**：味方の誰かが撤退中になったら、残りの味方は帰還・逃げをやめて攻め切り、なるべく早くそろって撤退する（本人：撤退中の人数 n に対して徳が n² で増えるので、そろって撤退した方が徳が溜まる。復帰もそろうので次の攻めを全員で始められる）。rush・counter に付けた版（rush＋w・counter＋w）を作る

数値（敵の撤退人数の閾値など）は CONFIG に置き仮置き。マクロの中身が上の説明と違う形になる場合は、止めて聞く。

## 2. 比較の実験
- 対 rush：steal・counter・counter＋w・split・rush＋w・std・farm（std・farm は基準）
- 対 std：steal・counter・counter＋w・split・rush＋w
- 1組20試合、陣営を入れ替えて半分ずつ。差が分からない組だけ20試合足す。公開サーバーに人がいる間は止める
- 表は botai2 と同じ項目（勝率と95%区間・大将ダメージ・デス・徳の増減・スロット当たり・時間の割合）に、「敵陣の資材を取った数」「counter の逆襲に入った回数と、その時の大将ダメージ」を足す

## 3. 結論の書き方
- 「rush に勝ち越すマクロがあったか（95%区間の下限が50%を超えたか）」を最初に1行で書く
- 無かった場合、どの数字が足りなかったか（大将ダメージ・徳・スロット当たりなど）を書く。調整の案は書いてよいが、数値は変えない
