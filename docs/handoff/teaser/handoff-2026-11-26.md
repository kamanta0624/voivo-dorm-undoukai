# ティザー動画撮影 引き継ぎメモ（2026-11-26）

## 目的
『ブイブイブレイカーズ（V V BREAKERS）』の X 投稿用ティザー動画（各5〜10秒、1280×720、mp4）を約10本、公開ビルド https://vv.club-daiman.com から撮影する。投稿文は全本共通で「こんなゲーム作ってます。4vs4オンライン対戦です」。

## なぜ Mac で撮るのか（実測済み）
Muse の VM 内ブラウザはソフトウェア描画で、実測のゲーム描画フレームレートが以下の通り使い物にならなかった：
- 1280×720・録画あり：5.1 fps／録画なし：8.6 fps／854×480・録画あり：6.6 fps

カメラ追従（CAM_LERP 0.08）は Phaser の仕様で「1フレームごとの割合」で効くため、5fps では追いつきに約2.5秒かかり、移動中の自キャラが約420px画面端に寄り続ける（実機60fpsでは約0.2秒で収まる）。ズレ以前に映像自体が約5fpsの紙芝居になるので、VM撮影は中止し、実機（Mac）での撮影に切り替えた。

## 撮影スクリプト（scripts/ 同梱）
Playwright（playwright-core）で公開ビルドに接続し、練習モード（1vs1）で場面を作って録画する一式。実績：
- `lib.mjs`：共通基盤（接続、キャラ選択、練習参加、移動、スナップショット読み取り、Watcher によるイベント記録、settle＝カメラ静止待ち）
- `fpsprobe.mjs`：描画 fps の実測用。**最初にこれを Mac で実行し、約60fps が出ることを確認してから本撮影に入ること**
- `p_wall3.mjs`：壁破壊（花丸のパッシブで壁に押し込む）— VM 上で成功実績あり（success=true）
- `p_sora.mjs` / `p_mochiko.mjs` / `p_yurei.mjs` / `p_kiritan.mjs` / `p_kiritan2.mjs` / `p_wall4.mjs`：各場面の台本の下書き
- `r_match.mjs`：通常ルーム参加用

### Mac 向けに直す箇所（lib.mjs）
1. `CHROME`（92行目）：VM の headless shell のパスになっている → Mac の Chrome／Playwright の chromium のパスに変更
2. `launch()`（96行目）の `proxy: { server: 'http://127.0.0.1:18080' }`：VM の中継用 → **削除**（Mac は直接接続）
3. 先頭の `createRequire('/home/hatch/work/voisq/package.json')`：playwright-core の解決用 → Mac 上のゲームリポジトリの package.json に変更（なければ `npm i playwright-core`）
4. 録画は webm で出るので、ffmpeg で mp4（1280×720）に変換して納品

## 撮影の約束事
- 見せ場の直前に約2.3秒静止してカメラを自キャラに落ち着かせる（lib の `settle()`）。キーフレームで主役が画面中央付近にいること
- 各クリップで開始／中間／終了の3フレームを抜いて目視確認してから納品する（主役が画面外・端のカットは撮り直し）
- 本番サーバーへの同時接続は1クライアントのみ。場面作りは練習モード優先
- 撮れなかった場面は捏造せず、正直に「撮れなかった」と報告する
- **注意：公開ビルド（f60ee4f）のタイトル画面はまだ旧タイトル「VOICE SQUAD」表示**。タイトルが映るカット（特に a）は、タイトル差し替えが公開ビルドに反映されてから撮るか、映らない範囲で切ること
