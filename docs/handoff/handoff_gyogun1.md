## これまでの決まり（本人。変えない前提で試作する。ぶつかる所は試作で両方見せる）
- 魚群は「キャラの群れ」で表現する（魚ではなくドット絵のキャラ）
- 通常版と、画面全体の視界外を使う特別版の2段階。信頼度で差を付ける

## 0. 試作（ここで止めて本人が選ぶ。ゲーム本体には入れない）
- スロット単体ページ（slot.html）か開発用のページで、実際の戦闘画面のスクショを背景に重ねて動かす。スマホ（852×393）と PC の両方の録画（各案 数秒）と、代表の静止画を verify/evidence/gyogun1/ に出す
- 「群れ」に見えるための条件（参考ページの魚群・群予告の特徴から）：数が多い／**複数の段**で、段ごとに位置と速さをずらす／密に重なり合う／同じ向きに画面を端から端まで横切る／一目で「何か大量に通った」と分かる量
- 案（最低この3つ。ほかに良い案があれば足す）：
  - 案A：視界の外だけ（今の決まりのまま）。視界の外の空きを、複数の段でぎっしり埋めて横切る
  - 案B：視界の中も含めて、画面を横切る帯（数段ぶんの高さ）。操作の邪魔にならないよう、ゲームの絵より手前・HUD より奥。濃さを2種類（そのまま／半透明）
  - 案C：通常版は案A、特別版は案B（画面の大半を埋める）
- 体数と段数は Code が複数出す（例：通常 30体・3〜4段、特別 80体以上・画面の高さの大半）。数字は目安で、決めるのは本人
- 全回転も、本人がいつでも見られるようにする（試作のページにボタン）。実機で出ないのは確率の仕様なので、確率は変えない

## 1. 実装（本人が案を選んだ後）
- 選ばれた案をゲーム本体へ。信頼度・出る条件・確率は変えない（見た目だけ）
- 描き方は、DOM の要素を並べるのでなく、**ゲームの canvas（Phaser）の中に描く形を先に検討する**。理由：体数が増えても DOM の書き換え・層が増えない／視界の外に切り抜く処理を Phaser 側の視界のマスクでできれば、43 で例外にした「演出の範囲のマスク（mfxArea が SVG を作り直す）」を無くせる。難しい・見た目が変わるなら、理由と DOM での案（transform・opacity だけで動かす）を報告
- ちび（リーチ演出のもう1つ）も同じ描き方に寄せられるなら、案として出す
