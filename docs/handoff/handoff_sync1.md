# Code引き継ぎ：sync1（出来事の時刻合わせ・巻き戻し時刻の検証・残り秒を終了時刻で送る）

2026-11-28 Chat作成。対象：~/kiritan_zunda_proto。refac3 の後。不明点は勝手に判断せず本人に確認。範囲外のコード・コメントは変えない。

## 狙い
クライアントの絵とサーバーの結果のずれを減らす。描画の安定（飛び・逆戻りを増やさない）は崩さない。

## 今の作り（Chat が読んだ範囲）
- 自キャラは予測で「今」を描き、他キャラ・弾は NET_INTERP_DELAY(0.2秒) 過去を補間で描く。被弾の演出と HP は補間の時刻に合わせてある（fxQueue の at・interp.hpAt）
- 近接AAだけ、入力に載せた描画時刻 rt まで相手を戻して判定（上限 NET_REWIND_MAX 0.35秒）

## やること
### 1. 単発の出来事を絵と同じ時刻に出す
- ko・koed・kill・assist・assistUp・recalled・bossHit は届いた瞬間に出しているが、画面の世界は 0.2秒過去。カットイン・キルログが撃破の絵より先に出る
- サーバーの送信に時刻（スナップショットの t と同じ時計）を載せ、クライアントは interp.reached(t) になってから出す（fx と同じやり方）
- 対象外：slot・penalty・mslot 系（盤面の絵と対応しない）、cm・cmStop（実況）、notice。迷うものは変えずに報告

### 2. 巻き戻し時刻の検証
- 今は rt をクライアントの申告のまま使う（上限だけ）。常に最大を申告すれば、近接が常に 0.35秒ぶん有利
- 成功基準で渡す（やり方は Code が案を出す）：
  - 常に最大の rt を申告するクライアントでも、巻き戻し量が「サーバーが測ったそのクライアントの遅延＋NET_INTERP_DELAY＋許容（CONFIG）」を超えない
  - 正常なクライアントの巻き戻し量は、変更前との差が許容以内（lagcomp1 で良くなった近接の当たりを悪くしない）

### 3. 残り秒を終了時刻で送る
- cd・skillCd・respawnIn・ult.left・warns の left・buffs などは「残り秒」で送っており、受信の揺らぎの分だけ表示がずれる
- サーバーの時計での終了時刻で送り、クライアントは interp の時計合わせ（offset）から今のサーバー時刻を出して残りを計算する
- サーバーに時計が複数ある（now・elapsed、e2e の早送り、決着演出のスロー）。どの時計で送るかを先に整理し、合わない所があれば止めて報告

## 成功基準
- 遅延100ms＋揺らぎ50ms を入れた状態で：撃破カットイン・キルログが撃破の絵と同じスナップショットの時刻（±1つ）で出る／クールタイム・復活の表示が逆戻りも飛びもしない
- 巻き戻しの2つの基準（上の 2）を verify のテストで確かめる
- verify/golden.ts が一致（試合の状態は変わらないはず。変わったら止めて報告）
- typecheck・test:server・e2e（全体1回）が通る。e2e は増やさない

## 範囲外
補間の遅延の可変化（保留。この後のテストプレイで要否を本人が判断）、弾・技への巻き戻しの拡大（やらない）、スナップショットの分割（sync2）
