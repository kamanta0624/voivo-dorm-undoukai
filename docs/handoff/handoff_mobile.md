# 引き継ぎ：スマホ対応（~/kiritan_zunda_proto）

## 目的
現行のPCブラウザ（WASD）版を、スマホのブラウザ（iOS Safari / Android Chrome）でも遊べるようにする。PC版の操作と挙動は変えない。

## 決定事項
- 技の操作は自動照準。タップで発動し、対象は現在の対象モード（一番近い／HP最低／大将優先）に従う。ドラッグで狙う操作は作らない
- PCとスマホの混在マッチを許す。端末による区別やマッチ分けはしない
- 表示は整数倍を維持する。余白が出てもかまわない
- PWA化する（iOSでホーム画面に追加すれば全画面で遊べるようにする）

## 作業
1. 現行のキー入力をすべて洗い出して報告する（移動、技、Q長押しのリコール、対象モード切替、ほか）。この段階で実装には入らない
2. 入力抽象化層：キーボードとタッチを同じ入力コマンドに変換する。サーバーとゲームロジックは変えない
3. タッチUI（スマホのときだけ表示）
   - 左下：仮想スティック（触れた位置に出るフローティング式）
   - 右下：技ボタン（クールタイムを表示）、リコールボタン（長押し）、対象モード切替ボタン
   - 同時タッチ数を増やす（`input.addPointer`）
4. 画面
   - 横向き前提。縦向きのときは「横にして」の表示を出す
   - ノッチ対策（`env(safe-area-inset-*)`）。HUD・ミニマップとタッチボタンが重ならないようにする
5. ブラウザ挙動の抑止：スクロール、ピンチ、ダブルタップでの拡大、長押しメニュー、テキスト選択
6. 音声：最初のタップで音声を有効にする（iOS）
7. ネットワーク：バックグラウンドから戻ったときにColyseusで再接続する
8. PWA：manifest、アイコン、`display: standalone`、横向き指定。オフライン対応はしない
9. 性能：視界のレイキャスト・マスクのフレーム時間を計測できるようにする。重かった場合の対策は報告し、勝手に入れない

## 成功基準
- DevToolsのモバイルエミュレーション（iPhone・Androidの横向き）で、移動・技・リコール・対象モード切替がすべてタッチで操作できる
- 移動しながら技ボタンを押せる（同時タッチ）
- 操作中にスクロール・拡大・長押しメニューが起きない
- PC版の既存テストがすべて通る。WASD操作に変化がない
- スマホ1台とPC1台が同じ部屋に入って対戦できる
- 実機確認の手順（LAN内のスマホからHTTPSでアクセスする方法）を書き残す

## 守ること
- 不明点は勝手に決めず、確認する
- 最小限のコードにする。投機的な実装や不要な抽象化はしない
- 指示の範囲外のコード・コメントは変えない
- 素材（32dot・立ち絵）は加工しない
- e2eテストを増やさない。入力抽象化層は単体テストで確かめる
