# Code引き継ぎ：perf5（毎フレームのレイアウト・スタイル再計算をなくす）

2026-11-25 Chat作成。対象：~/kiritan_zunda_proto。screen1 の後に着手（main.ts の HUD 周りが重なるため）。
不明点は勝手に判断せず本人に確認。範囲外のコード・コメントは変えない。描画・UI は docs/render_policy.md に従う。

## 背景
tune7 の3章（連戦の計測）で、連戦でたまるものは見つからなかった。一方で、試合中は1フレームあたり約1回、レイアウトとスタイルの再計算（Recalculate Style・Layout）が起きていた。iPhone 15 Pro（PWA）が何試合かで熱くなる件は、この毎フレームの負荷の線が濃い。render_policy 5（DOM は値が変わった時だけ書き換える）に反している箇所がある疑い。

## やること
1. 計測：Bot戦の試合中（通常・乱戦・スロット演出中・撤退中）で、Chrome のパフォーマンストレース（ヘッドレスでよい）を取り、再計算・レイアウトを起こしている呼び出し元（ファイル・行）を一覧にする。読み出し（getBoundingClientRect・offsetWidth 等）による強制レイアウトも含める
2. 値が変わらないのに書いている所は、変わった時だけ書くようにする（前回値と比べる、要素の参照を使い回す等）。動きが要る物は transform・opacity にする
3. 毎フレーム変わるのが仕様の表示（例：残り時間の秒数）は、書き換えを値の変化時だけにすれば足りるか確認する。それでも毎フレーム再計算が残るなら、場所と理由を報告
4. 調べるだけ（直さない）：tune7 で微増した「切り離された DOM ノード数」と「Document の数（3→10）」がどこで作られているか（ファイル・行）。直し方の案を報告

## 成功基準
- 1の一覧（直す前）と、直した後のトレースで、試合中の1秒あたりの再計算・レイアウトの回数と時間を前後で比べた表がある
- 直した後、何も変わらないフレームでは再計算・レイアウトが起きない（残るものは理由つきで一覧）
- ?perf=1 の1フレームの処理時間が悪くなっていない（前後の表）
- 見た目・動きが変わっていない（Bot戦で通常・撤退中・スロット演出中のスクショを前後で比較）
- typecheck・test:server・e2e（全体1回）が通る。e2e は増やさない

## 不明なら止めて聞く
- 直すと見た目・操作感が変わる箇所
- 直す範囲が main.ts の大半に及ぶ場合（案を出して止める）

範囲外の変更、不要な抽象化、素材の加工、e2e の追加、fps 上限の追加、公開サーバーの停止
