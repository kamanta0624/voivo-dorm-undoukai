## 本人の判断
- 今の検証でバランスを調整するより、先にマクロを磨く。tune8 は保留（実装しない）
- botai1 のマクロは「何もない時にどこへ向かうか」を試合開始時に固定で決めるだけなので、farm とパワーアップを過小評価している可能性がある

## 本人の指摘と、足す判断（全マクロ共通の層として足す。数値は CONFIG に置き仮置き）
1. **パワーアップしたら攻める**：パワーアップ中のキャラは、元の役割（資材など）に関係なく「攻め」に切り替える。パワーアップが終わったら元の役割に戻す
2. **アシストと足並みをそろえる**：味方のアシストが出ている間、味方の一部に「同行」の役割を一時的に付ける。同行役はアシストのそばについて一緒に動き、アシストの近くの敵と戦う。アシストが単騎で攻め込んで倒されるのを防ぐのが目的
   - 何人に付けるか（仮：アシストに近い生存者2人）、アシストの方を待たせるか（味方がそろうまで進まない等）は、Code が案を出して決めてよい。決めた内容と理由を報告
3. **adv は廃止**：「生存数が多い間だけ攻める」は、数的有利がすぐ解消されるので意味がない。比較から外す（1・2 が「攻め時に攻める」の代わりになる）
4. **守りは終盤のリード時だけ**：常駐の守り役（guard）はやめる。代わりに「残り X 秒（仮：60秒）で、大将HPの割合でリードしていたら、全員が守りに入る」判断にする
   - 守りの動きは今の guard 役（自陣の大将のそばで待ち、近づいた敵を迎え撃つ）を使う。botai1 で守りが効いていなかった（守っても自陣の大将の残りが一番少なかった）ので、効かない理由を調べて報告し、直せるなら直す

## 比較の実験
- 物理（操作の上手さ）は全部「中」。強・弱の比較はしない
- 比べるマクロ：std・rush・farm のそれぞれに、上の 1・2・4 を足した版（「＋」とする）を作る。1・2・4 のどれが効いたか分かるように、std に1つずつ足した版（std＋1・std＋2・std＋4）も作る
- **試合数を減らす（本人）**：総当たりはしない。全部を std（今の本番）とだけ戦わせる。std＋・rush・rush＋・farm・farm＋・std＋1・std＋2・std＋4 の8組
- 1組み合わせ20試合、陣営を入れ替えて半分ずつ（計160試合）。公開サーバーに人がいる間は止める
- 20試合で勝率の95%区間が50%をまたいだ組（差が分からない組）だけ、20試合を足す。足しても分からなければ「差が分からない」と書いて終わる
- 報告の形は botai1 の2章と同じ表（勝率・大将ダメージ・デス・徳の増減・スロット当たり・時間の割合）に、「パワーアップ中に攻めていた時間」「アシストに同行していた時間」「終盤の守りに入った試合の割合と、入った時の勝率」を足す
