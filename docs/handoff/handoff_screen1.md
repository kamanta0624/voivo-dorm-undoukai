# Code引き継ぎ：画面の倍率と左右余白（screen1）
対象：~/kiritan_zunda_proto（開発側）。handoff_hud2 の後に着手（どちらも main.ts のHUD周りを触るため）

## 背景
横長の画面（スマホ・ブラウザ）で両端と上下が黒く大きく余る。原因は `main.ts` の `zoom()` が CSS 画素で整数倍に切り捨てていること（例：CSS高さ393・DPR3のiPhoneで1倍＝360、DPR2.625のAndroidで1倍＝360/412）。

## A. 倍率（ドットを崩さないことが最優先）
1. 倍率を実画素で整数倍にする：実画素の倍率 = floor(min(幅×DPR/VIEW_W, 高さ×DPR/VIEW_H))、表示上の zoom = その値/DPR
2. 論理解像度（640×360）・視野・縮尺は変えない。ドットの1画素が実画素で均一な正方形に描かれること
3. 現行の「タッチ端末で1未満のとき」の扱いは残す（実画素で1倍も取れない小さい画面だけ）
4. zoom が非整数になるので、`--z` で拡大しているHTMLの重ね表示（#fx、キルログ、カットイン、スロット演出 mfxl、タッチのスティック等）の位置と大きさがずれないか確認し、ずれるなら直す
5. 回転・リサイズで追従すること（現行の resize・orientationchange）

## B. 余白（ゲーム画面の外）
6. ゲーム画面の外（左右・上下とも）に背景を敷く。全画面（タイトル・選択・待機・観戦・対戦中）で出す。対戦中は自キャラごとの色（キャラごとに立ち絵となんとなく合う色。値は chars.json などキャラ定義に1項目足して仮置き、本人が後で直す）、それ以外は共通の既定色（仮置き）
7. 右の余白（既定）：自キャラの立ち絵（Moiky、`select` の表情で固定）。撃破・撤退・反省中などで差し替えるのは今回やらない。スマホは自撮りカメラが左に来る向きで持つことが多いため、立ち絵を右にする
   - 大きさ・位置は仮置き（案：高さはゲーム画面の高さ、ゲーム画面側に寄せて下揃え、余白に収まらない分は外側（画面の端側）を切る。ゲーム画面の上には被せない）
   - 立ち絵は高解像度のまま表示する（論理解像度に縛らない。既存のカットインと同じ扱い）
8. 左の余白（既定）：背景色だけ。将来スロット演出に使う場所。今回は何も置かない
8b. 立ち絵と演出用の余白の左右を入れ替えるオプション：キャラ選択画面の「実況 ON/OFF」ボタン（#cmbtn）の隣に切替ボタンを置き、端末に保存（localStorage、実況と同じ扱い）。ゲーム画面内のHUD・ボタンの配置は入れ替えない
9. 余白が無い・ほぼ無い画面では、描画はするがほとんど見えない状態でよい（隠す処理は不要）
10. 余白が非常に大きい画面で背景が続いて寂しくなるのは承知の上。今回は対策しない
11. 立ち絵とキャラ色の背景は対戦中（自キャラが決まって試合が進んでいる間）だけ。タイトル・選択・待機・観戦は既定色の背景だけで立ち絵なし
12. 余白の表示物はゲームの入力（タッチのスティック・クリック）を邪魔しない（pointer-events を通す。現行の入力範囲は変えない）
13. 切り欠き（自撮りカメラ）に余白の中身が重なってもよい（見えない部分が出るだけ）。セーフエリアの考慮は不要

## 成功基準
- DPR3（iPhone相当、852×393）・DPR2.625（Android相当、915×412）・DPR2（Mac Retinaのブラウザ）・DPR1（1920×1080のブラウザ）の4つで、ゲーム画面の倍率・上下左右の余白の大きさ・ドットの均一さをスクショで報告（DevToolsの端末エミュレートでよい）
- 対戦中は余白にキャラ色と立ち絵（既定は右、切替で左）、タイトル・選択・待機・観戦は既定色だけが出ている。スティック・ボタン・ミニマップ・HTMLの重ね表示がずれていない
- typecheck・test:server が通る。e2e は増やさない

## 不明なら止めて聞く
- Phaser の倍率指定で実画素の整数倍が取れない・ぼやける場合（canvas の解像度の持ち方を変える必要がある場合）
- 重ね表示の直しが広範囲（main.ts の大半）に及ぶ場合

## 禁止
範囲外の変更、不要な抽象化、素材（立ち絵）の加工、論理解像度・視界の変更、e2e の追加
