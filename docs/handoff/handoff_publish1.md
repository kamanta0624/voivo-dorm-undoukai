# Code引き継ぎ：公開準備1（ロビー・名前・キック/BAN・同時接続上限・負荷試験・常駐化）
対象：~/kiritan_zunda_proto
前提：f73ed1b（playtest2）。ドメイン未取得のため、名前付きトンネル化は今回の対象外（cloudflared は一時トンネルのまま）

## 公開サーバーを落とさない（最優先）
- 改修・検証は別フォルダ・別ポート（GAME_PORT・CLIENT_PORT）。稼働中のゲームサーバー・dist/・cloudflared に触らない
- 公開版への反映はしない（反映は本人の指示で、まとめて tools/deploy.sh <タグ> で行う）。cloudflared は触らない
- 手順どおりにできない事情があれば止めて聞く

## 前提の整理（現行コード）
- 部屋は `joinOrCreate('game')` で自動。MAX_CLIENTS=16（超過分は観戦）で、満室なら Colyseus が新しい部屋を作る。部屋数の上限はない
- プレイヤー名はない。待機画面はキャラ名のみ

## A. 入口（タイトル → 名前 → 入室）
1. 最初の画面で名前を入れる。長さ上限は定数（仮置き：10文字）。前回の名前をブラウザに保存して初期値にする
2. 入室方法は2つ：
   - 「おまかせ」：現行どおり空いている公開部屋へ（joinOrCreate）
   - 「合言葉」：合言葉を入れて入る。その合言葉の部屋がなければ作る。合言葉部屋は「おまかせ」では入れない
3. 合言葉は部屋の中（待機画面）に表示し、コピーできる
4. 再接続（RECONNECT_SEC）・e2e の別部屋（?e2e=）は現行どおり動くこと

## B. 名前
5. NGワード判定：単語リストのファイル1つ（docs ではなく設定ファイル。中身は本人が足す。最初は空に近くてよい）。部分一致したら入室させず、名前の入れ直しを促す
6. 表示は待機画面の組の一覧だけ（キャラ名と並べる）。キルログ・カットイン・実況には出さない
7. 同じ部屋で名前が重複したら末尾に番号を付ける

## C. 同時接続上限
8. サーバー全体の部屋数の上限を定数で設ける（仮置き：2部屋）。e2e の部屋は数えない
9. 上限に達して新しい部屋を作れないときは「満員です。しばらくしてから来てください」を表示する（おまかせ・合言葉どちらも）
10. 既存の部屋への入室（観戦枠を含む）は MAX_CLIENTS まで従来どおり
11. 試合終了後に全員いなくなった部屋は破棄され、枠が空く（現行の挙動を確認して報告。破棄されないなら直す）

## D. 管理ページ（キック・BAN）
12. `/admin` を同じポートで配信。パスワードは環境変数（未設定なら /admin を無効）。パスワードはコード・ログに書かない
13. 表示：部屋ごとの合言葉の有無、フェーズ、参加者（名前・キャラ・人/Bot・IP）。手動更新でよい
14. 操作：
    - キック：その人を部屋から外す。枠は現行の切断と同じく Bot が引き継ぐ（再接続させない）
    - BAN：キック＋以後の入室を拒否。判定は IP（`CF-Connecting-IP`、なければ接続元）とブラウザ保存IDのどちらか一致
    - BAN解除
15. BAN一覧は `logs/bans.json` に保存（logs/ は gitignore 済み）。サーバー再起動後も有効
16. BANされた人には「入室できません」とだけ表示する

## E. 負荷試験
17. 試験用スクリプト（tools/ に1つ）：別ポートでサーバーを起動し、部屋を 1→2→4→8→12 と増やす。各部屋に node から SDK のクライアントを8つ接続して試合を進める（入力は Bot 相当でよい）
18. 部屋数ごとに記録：1tick の処理時間（平均・最大・99%）、TICK_HZ の間隔に収まっているか、CPU使用率、メモリ、サーバーからの送信量（合計とクライアント1人あたり、毎秒）
19. 結果を表で報告。このMac（Wi-Fi）で何部屋まで現実的か、ボトルネックは何か（CPU・送信量）の所見も
20. 試験は公開サーバーと同時に動かすので、試験中の公開版への影響（公開中の試合の有無）を確認してから走らせる。判断がつかなければ止めて聞く
21. 試験結果を見て部屋数の上限（C-8）の値は本人が決める。Code は変えない

## F. 常駐化（ゲームサーバーのみ）
22. ゲームサーバーを launchd に登録する plist を用意する（落ちたら自動再起動、ログは logs/server.log へ追記、SERVE_DIST=1）
23. 別ポート・別ラベルで plist の動作を確認（kill しても再起動する、ログが出る）
24. 公開中のサーバーを launchd 管理に切り替えるのは本人の指示を受けてから。切り替え手順（どのPIDを止め、何を load するか）を書いて止める
25. cloudflared は launchd に入れない（一時トンネルは再起動でURLが変わるため。ドメイン取得後に別途）
26. スリープ防止は sudo が要るので本人が行う。必要な `pmset` コマンドを報告に書くだけ

## 成功基準
- A〜D：別ポートで、2つのブラウザで「おまかせ」と「合言葉」それぞれ同じ部屋に入れる。違う合言葉は別部屋。部屋数の上限で「満員」が出る。NGワードで弾かれる。管理ページでキック・BAN・解除ができ、BANがサーバー再起動後も効く。スクショで報告
- verify/server.ts に追加：合言葉で同じ部屋に入る／上限で入室拒否／BAN一致で拒否
- E：表が出ている
- F：別ポートで自動再起動を確認、切り替え手順が書いてある
- 既存の再接続・バージョン表示・matches.jsonl・Bot戦が従来どおり。typecheck・test:server が通る。e2e は増やさない

## 不明なら止めて聞く
- Colyseus 0.18 で onAuth からヘッダー（CF-Connecting-IP）が取れない場合
- 合言葉部屋の実装に filterBy 以上の大きな改修が要る場合
- 入口の画面追加で既存の待機画面・スマホ表示に大きな改修が要る場合

## 禁止
範囲外の変更、不要な抽象化、素材の加工、e2e の追加、公開サーバーの停止（指示後の切り替え・ゲームサーバーの差し替え以外）、cloudflared の変更
