# Code引き継ぎ：sync2（スナップショットの量を測る → 静的・動的に分ける・敵向けの項目を絞る）

2026-11-28 Chat作成。対象：~/kiritan_zunda_proto。sync1 の後。不明点は勝手に判断せず本人に確認。範囲外のコード・コメントは変えない。

## 狙い
毎tick（毎秒20回）、全部の状態をクライアントごとに組み立てて送っている（roster・broken・bossRooms・materials・items・各キャラの maxHp・cdMax・char なども毎回）。量を減らして、無線の詰まりから来る揺らぎの元を減らす。

## 0. 計測（ここで止めて報告）
- 通信の計測（netmeasure）に、スナップショットのバイト数（クライアントごとの平均・最大・毎秒の合計）を足す
- 4vs4（人間1＋Bot、観戦1）で1試合ぶん測り、項目ごとの内訳の目安と一緒に報告
- 分けても効果が小さいと見えたら、その旨を書く。1 以降に進むかは本人が決める

## 1. 静的・動的に分ける（本人の確認後）
- 変わった時だけ送るもの：roster、bossRooms、broken、materials・items（増減した時）、各キャラの変わらない・めったに変わらない項目（char・team・bot・assist・tier・maxHp・cdMax など。Code が洗い出す）
- 毎tick 送るもの：位置・HP・向き・状態など、動くもの
- 入室・再接続・ページの読み直しの時は全部を送り直す（壁の段階 crackSent と同じ考え方）
- クライアントの補間・予測の入力（t・位置・ack）は今と同じ値・同じ時刻で届く

## 2. 敵向けの項目を絞る
- 見えている敵について、クライアントが実際に描画・表示に使っている項目を洗い出し、それ以外は敵には送らない（候補：skillCd・cd・aim・tgt・spd・ack・bad など。改造クライアントで敵のクールタイムが見える）
- 仕様として見せているもの（例：敵のリコールの溜め、パワーアップの残り）は残す。迷うものは外さず一覧で報告

## 成功基準
- バイト数の前後を報告（毎秒の合計・最大）
- 途中入室（観戦）・再接続・ページの読み直し・連戦（結果画面 → 待機 → 次の試合）で、表示が欠けない・古い値が残らない
- 補間・予測の計測（netmeasure の補間の成績・補正の量）が悪化しない
- verify/golden.ts が一致。typecheck・test:server・e2e（全体1回）が通る。e2e は増やさない
