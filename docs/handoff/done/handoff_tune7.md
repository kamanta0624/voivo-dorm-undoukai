## 公開サーバーを落とさない
- 検証は別ポート（GAME_PORT・CLIENT_PORT）。公開側（~/kiritan_zunda_proto_live、launchd の com.vvsports.game・com.vvsports.tunnel）は読むだけ
- 公開版への反映は末尾の手順だけ

## 1. リーチ演出「カットイン」をやめる
- 画面右下の隅に枠付きの Moiky 立ち絵を出すリーチ演出（config.ts の SLOT 演出 reach.cutin、slot_modern_fx.ts の act === 'cutin'）を削除する
- リーチの発生率・当選率は変えない（reach の重みから cutin が抜けるだけ。残りの演出の比率はそのまま）
- スロット単体画面（slot_page）でも出なくなること
- ルール説明・更新情報に記載があれば合わせる

## 2. 「たまに処理が重い」の調査（直さない）
- 公開版の logs/matches.jsonl を `npx tsx tools/netmeasure.ts` で読み、直近の試合で重くなった区間を特定する
- 原因を切り分けて報告：通信（遅延・揺らぎ・欠損）／サーバーの tick 超過／クライアントの描画（フレーム落ち）。分かる範囲でどの場面（乱戦・スロット演出・壁破壊・視界の描き直し等）と重なるか
- 計測が足りず切り分けられない場合は、何を足せば分かるかを書いて止める
- 修正は報告後に本人が判断する

## 3. 試合を重ねるごとに重くなるかの確認（直さない）
- 本人の報告：iPhone 15 Pro（PWA、60fps付近に設定済み）で何試合かするとスマホが熱くなる。fps 上限は付けない
- 同じブラウザで連戦（Bot戦、待機画面に戻る→次の試合を5回）し、1試合目と5試合目で比べる：1フレームの処理時間（?perf=1）、JS のメモリ、Phaser のオブジェクト数・テクスチャ数、DOM の要素数、鳴らした音声の数、イベントリスナーの数
- 増え続けるものがあれば、どこで作って片付けていないか（ファイル・行）と直し方の案を報告
- 計測はヘッドレス Chrome でよい。iPhone 実機で確かめる手順が要るなら本人向けに書く

## 4. 練習パネルをスクロールできるようにする
- 本人の報告：iPhone 15 Pro（PWA・横向き）で練習パネル（.prw/.prp）の下側が画面で切れ、「パワーアップ 相手」より下に届かない
- .prp には overflow-y:auto が既にある。原因の候補：main.ts 327行の document の touchmove を一律 preventDefault（画面のスクロール防止）と、134行の html.touch の touch-action:none。パネル内（.prp）のタッチだけ縦スクロールを許す。画面全体のスクロール防止は残す
- 見た目・中身の並びは変えない

## 成功基準
- 1：試合・スロット単体画面で、リーチ時に右下の立ち絵が一度も出ない（Bot戦でリーチ発生を確認、スクショ1枚）。typecheck・test:server が通る。e2e は増やさない
- 2：重い区間ごとに原因の分類と根拠の数値がある
- 4：スマホ表示（iPhone 横向き相当の小さい画面）で練習パネルを指でスクロールして最下部の項目まで押せる。PC のホイールでも同じ。スクショで報告
- 3：1試合目と5試合目の比較表があり、増え続けるものの有無と場所が書いてある
