# 引き継ぎ書: lagcomp1（近接AAの表示遅れ対策: 補間遅延の短縮＋巻き戻し判定）

対象: ~/kiritan_zunda_proto（開発側）。公開側への反映はしない（本人の指示でまとめて deploy.sh）。

## 背景（Chat の調査結果、コードからの見積もり・実測なし）
- 症状: 移動速度が高いと近接AAが当たらないように見える。あいえるたんの加速（約281px/秒）で顕著
- サーバーの判定自体は一貫している（pickTarget と attack の inArc は同じ射程。GameRoom.ts 773・1026行付近）。届いていないので攻撃が出ていないだけ
- 原因: 他キャラは NET_INTERP_DELAY（0.25秒）過去を補間して描き、自キャラは予測で先に描く。逃げる相手（約187px/秒）を加速中に追うと、画面とサーバーの距離差が約75px（相手 47px＋自分 約28px）で、近接の届く距離（射程50＋半径10＝60px）を超える
- 斬撃エフェクト（aaFx の slash）はサーバー位置に出るため、移動中は自キャラの後ろに出て空振りに見える

## 1. 補間遅延の短縮
- config.ts の NET_INTERP_DELAY を 0.25 → 0.2（0.1・0.15 は verify/net.ts の揺らぎ100msケースでワープが出るため、2026-11-21 本人判断）
- 成功基準: verify/net.ts が通る。ブラウザで他キャラの移動が目立ってカクつかないか確認し、気になる点があれば報告（判断は本人）

## 2. 近接AAの巻き戻し判定（ラグ補償）
- 人間プレイヤーの近接の通常攻撃（ウルト中の近接の変身を含む）だけ、攻撃した人の画面の時刻での相手の位置で判定する。弾・技・Bot は今のまま
- クライアント: 入力（room.send('input', ...)）に、その時点の描画時刻（interp.renderTime、サーバー時刻）を載せる
- サーバー: プレイヤー・大将・コバコの位置の履歴を tick ごとに短期間持つ。対象選び（pickTarget）と当たり（inArc・reach）で、相手の位置をその人の描画時刻まで戻して測る。攻撃した側の位置は今のサーバー位置
- 巻き戻しの上限は仮置き 0.35秒（超える分は上限で止める）。壁は今の壁で判定
- 自キャラの予測の先行分（入力遅延・順番待ち）は補償しない。必要そうなら案として報告のみ
- 成功基準:
  - verify に、追いかけ（攻撃側 281px/秒、相手 187px/秒で同方向、描画時刻を 0.2秒＋通信遅延ぶん過去に設定）で巻き戻しありは当たり、なしは当たらないケースを追加して通る
  - Bot 同士の試合結果（golden）が変わらない。変わったら理由を報告
  - npm run typecheck・test:server が通る

## 3. 斬撃エフェクトの位置合わせ
- 自分の近接の斬撃は、サーバー位置ではなく画面の自キャラの位置に描く（向き・射程・角度はサーバーの値のまま）。他人の斬撃は今のまま
- 成功基準: ブラウザで加速中に攻撃し、斬撃が自キャラから出ているスクショ
