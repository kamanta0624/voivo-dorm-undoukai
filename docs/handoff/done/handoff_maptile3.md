## 3. 家具・小物（部屋の用途を想像させる）
- 当たり判定なし・通り抜け可。間取り・動線・map.json は変えない。試験ページだけに描く
- BaseChip の家具・小物から、部屋ごとに用途が分かる物を置く。候補：
  書庫＝本棚／ランドリー＝洗濯機・物干し／物置＝棚・箱／会議室＝机・ホワイトボード／PCルーム＝PC机／音楽室＝楽器／LDK＝キッチン・食卓・ソファ／パーティールーム＝長テーブル・飾り／応接間＝応接セット／ジム＝トレーニング器具／アトリエ＝イーゼル・画材／工作室＝作業台・工具／階段ホール＝階段／自習室（屋外）＝机・ベンチ／サンルーム（屋外）＝植木・花壇
- 配置は壁際中心で、部屋の中央の通り道をふさいで見えないようにする
- 素材にない物は置かずに一覧で報告。素材の加工はしない
- 配置は部屋ごとの表（chips.ts か別ファイル1つ）にまとめ、本人が後で動かせるようにする

## 4. 視界を遮らない壁（ゲーム本体）
対象：
- アトリウム（entrance）の南の壁（ガラス）
- 自習室・サンルームの外側の壁＝建物の外（map.json の ' '）に面する壁（柵）
- 犬走り（corrTop）の壁も透過対象（柵）。既存の開口部はそのまま
- 検証はサンルームと犬走りの移動可能な床にキャラを置いて行う。侵入不可能エリアへ敵を置かない
仕様：
- 視界だけ通す。移動・攻撃・弾・自動照準・大将の索敵・Botの照準は今の壁と同じく遮る
- 視界＝サーバーの visibleTo（敵の表示判定）と、クライアントの視界マスク（main.ts の視界ポリゴン）。この2つが同じ壁を透過扱いにすること
- 今は lineOfSight を視界と射線の両方に使っている。視界用と射線用を分ける。射線側の挙動は変えない
- map.json に透過壁の区別を足す（例：新しいタイル文字）。壊せるかどうかは今の壁のまま
- 試験ページもこの区別を読んでガラス・柵で描く
確認：
- 型チェック・サーバー単体テスト・e2e を流す。golden が変わったら理由を報告（視界の変化で Bot の挙動が変わるなど）
- 透過壁越しに敵が見え、攻撃・弾は通らないことを検証項目に足す
- コミットは本人の確認後。公開版へは反映しない
