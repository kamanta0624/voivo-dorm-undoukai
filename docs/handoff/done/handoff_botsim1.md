# Code引き継ぎ：botsim1（誰もいない時に Bot 戦を回してログを取る）

2026-11-26 Chat作成。対象：~/kiritan_zunda_proto。不明点は勝手に判断せず本人に確認。範囲外のコード・コメントは変えない。

## 目的（本人）
誰も遊んでいない時に Bot 同士の試合を自動で回し、ログを貯める。後で「戦略（マクロ）とフィジカル（操作の上手さ）が勝敗にどれくらい効くか」を調べる土台にする（Bot の強弱・マクロは次の botai1）。
同じ記録は、人間が遊んだ試合の結果画面（result1）にも使う。

## 回し方
- 公開サーバーとは別プロセスで、ネットワークを通さず GameRoom を直接 tick する（tools/loadtest.ts の --server の作りが参考。描画・接続なし）。時間は実時間を待たずに早回しする。試合の中身（tick 幅・ルール・CONFIG）は本番と同じ
- 乱数は試合ごとに種を決めてログに残す（同じ種で再現できる）
- 公開サーバーと同じ Mac なので：
  - 公開サーバーに人間（プレイヤー・観戦）がいる部屋が1つでもある間は始めない。回している途中で人間が来たら、その試合を捨てて止める（判定の方法は公開サーバーの既存の口から選ぶ。無ければ案を出して止める）
  - 同時に回すのは1プロセス、nice で優先度を下げる。e2e が走っている間も始めない
  - launchd で定期的に起動（間隔・1回の本数・上限時間は CONFIG かスクリプトの引数で1か所に）。ゲームサーバーの launchd・deploy.sh・cloudflared には触らない
- 編成：キャラはランダム（PICKABLE から、本番の Bot の選び方と同じ）。e2e の固定編成（E2E_BOTS）は使わない

## 記録部の置き方（2026-11-26 改訂。リザルト画面 handoff_result1.md の元データも兼ねる）
- 記録は GameRoom の記録部（別ファイル可）が担う。**常時ON**（人間の部屋・Bot だけの部屋とも）。試合開始で初期化、終了で確定。メモリは1試合数百KB以内にする
- 記録部は試合終了後に `summary()`（JSON 化できる要約：推移・イベント・キャラ別合計。数KB〜数十KB）を返せる。result1 がこれをクライアントへ送る。送信そのものは result1 の範囲（本章では作らない）
- JSONL への書き出しは**人間の試合も Bot 戦も同じ**（本人決定 2026-11-26）。試合終了時に1回だけ追記する。公開サーバー（人間の部屋）と Bot 戦の別プロセスの両方が書く。同時追記を避けるため、ファイルは logs/matchlog/YYYYMMDD_human.jsonl と YYYYMMDD_bot.jsonl に分け、形式とキーは完全に同じにする
- 常時ONにしても tick 時間が悪化しないこと（成功基準）

## 取るログ（1試合1行の JSONL、logs/matchlog/ 配下。logs/matches.jsonl とは混ぜない。各行に source: "human"｜"bot"、キャラごとに human の有無。プレイヤー名は記録しない。種は人間の試合では再現できない（記録だけする））
- 試合：開始時刻・種・コードのコミット・秒数・勝敗と決着の種類・両チームの最終の各ゲージ（徳・スロット・大将HP など、試合終了時にある数値のゲージは全部。何を入れたか報告）
- スロット：回転ごとの時刻・チーム・当落・当選内容（ウルト／アシスト／7／フィーバー／ペナルティの種類など、今ある区分そのまま）。**揃った図柄（9種のどれか。当たりの種別＝キャラの図柄はそのキャラのパワーアップ、7は全員のパワーアップ、アシストの図柄はアシスト出現・強化、も記録）**も入れる
- キャラごと：キャラ・チーム・与ダメ／被ダメ（対キャラ・対大将・対コバコ・対壁を分けて）・キル・デス・アシスト（連携）・稼いだ徳・悪行
- Bot の挙動：キャラごとに状態ごとの滞在時間（gather／raid／リコール・食事／交戦／逃亡など今ある状態）、技・ウルトを使った回数、死んだ場所（部屋）
- 推移：1秒ごとに両チームの徳・両大将の HP
- 推移に追加（リザルト画面用）：(1) プレイヤーキャラごとと、アシスト（召喚物）合計の、1秒ごとの対大将ダメージ（閾値なし・全ダメージ）。(2) キャラごと（アシストが徳に関わるなら含める）の、1秒ごとの徳の「稼いだ分」と「減らした分」を別々に（正と負を分けて持つ。徳の上限・下限で打ち切られた分は数えず、実際にゲージが変化した量）。どちらも後から時間帯で合算できる粒度
- イベント（リザルト画面用。1件＝時刻秒・チーム・キャラ・種別・相手。プレイヤーキャラのみ。アシスト（召喚物）の撃破・被撃破はイベントにせず、キャラ別合計の「アシストキル」に数える）：
  - kill／death（撃破した側・された側それぞれ1件）
  - slot：スロットの当選・ペナルティ（上の「スロット」と同じ区分・内容。チーム単位）
  - koba：コバコ撃破（撃破したキャラ）
  - bossBig：大将への単発の大ダメージ（1回の damage 呼び出し。閾値は CONFIG 1か所、仮置き＝大将最大HPの5%。多段ヒットは各ヒットが閾値未満なら印が出ない＝許容。数値は報告）
- 推移の大将HPは割合（%）と実数の両方

## 集計とグラフ
- tools/ に集計スクリプトを1本。logs/matchlog/ を読み、1枚の HTML（依存なし、ローカルで開ける）を書き出す：
  - 全体／人間のみ／Bot のみ を切り替えられる（source で絞る。Bot 同士の結果と人間が混ざる場合は混ぜた数字を断定しない）
  - 試合数・勝率（チーム別、キャラ別の出場時勝率）、決着の種類の割合
  - キャラ別の与ダメ／被ダメ／キル／デスの平均
  - 徳と大将 HP の推移（試合を重ねた平均と幅）
  - スロット当選内容の時刻の散布（チーム色分け）
- 数が少ない区分は数も出す（少ない数の勝率を断定しない）

## 成功基準
- 手で1回起動して20試合回り、JSONL と HTML ができる（HTML のスクショ）
- 人間が入った試合を1回（e2e の人間クライアントで可）行い、source:"human" の行が出る。Bot 戦の行とキーの一覧が一致する（差分なしの確認結果）
- 公開サーバーに人間がいる状態を作ると始まらない／途中で止まる（確認の手順と結果）
- 回している間の公開サーバーの tick 時間（?perf=1 か loadtest と同じ計り方）が回していない時と比べて大きく悪化しない（前後の表）
- 本番のゲームの動きを変えていない。GameRoom への変更は記録部の呼び出し口だけ（記録は常時ON・軽量、書き出しは試合終了時に1回だけ）。記録ON/OFFで tick 時間が誤差内（?perf=1 か loadtest と同じ計り方で前後表）
- typecheck・test:server・e2e（全体1回）が通る。e2e は増やさない

## 不明なら止めて聞く
- 人間の有無の判定の口が無い場合
- logs/ の合計が大きくなりすぎる場合（Mac の空きは60GB（2026-11-26 実測）。上限を CONFIG に1か所、仮置き2GB。超えたら書かずに警告ログを出す。消さない。報告）
- ログ取りのために GameRoom の中身を大きく変える必要がある場合

## 禁止
範囲外の変更、不要な抽象化、e2e の追加、公開サーバーの停止、ゲームのルール・数値の変更
