## 1. 試合開始前の3秒（出撃）
1. 試合開始が決まった時（全員出撃、または15秒の選択猶予切れ）から3秒、選択画面のまま置いてから戦闘画面（intro）へ移る。秒数は定数 SORTIE_SEC＝3
2. この3秒の間に、各プレイヤーの端末で自分のキャラの出撃セリフを鳴らす（本人の端末だけ。字幕も出す）
3. この3秒を使って、戦闘画面で初めて読み込む・作るもの（マップのテクスチャ、キャラ・エフェクトの画像、実況・ボイスの音声のデコードなど）を先に済ませる。まず現状で戦闘画面に入った直後に何を読み込み・作っているかを洗い出し、3秒に移せるものを移す
4. 練習の部屋・e2e の部屋は現行どおり（3秒を挟まない）
5. 観戦者（spectate1）は3秒の間も観戦のまま

## 2. 出撃セリフ（キャラボイスの最初の1種）
6. セリフは本人が Google スプレッドシート「VOICE SQUAD 出撃セリフ」（列：キー・キャラ・番号・セリフ・メモ。各キャラ2本）で直し、CSV で docs/voice/sortie.csv に置く。Code はセリフを考えない・直さない。CSV が置かれるまで 2章は待つ（1・3〜6章は先に進めてよい）。鳴らすのはキャラごとにランダムに1本。docs/char_lines.md にも反映する
7. キャラボイスの仕組みを最小限で作る：CSV から VOICEVOX のプロジェクト（vvproj）を生成するスクリプトと、音声の書き出し。実況（tools/commentary.ts の cm:vvproj・cm:audio）の作りに合わせる。各キャラの VOICEVOX の話者は Code が対応表を作って報告する（該当する話者がいないキャラがいれば止めて聞く）
8. vvproj を作ったらここで止めて報告（追加したセリフの一覧、vvproj の場所）。音声の生成はしない
9. 本人が台本を直し、VOICEVOX で調声して保存する。本人から「調声済み」の指示を受けてから音声を生成して組み込む
10. 他の場面のボイスは今回作らない

## 3. HUD の配置換え
11. 左下のデバッグ表示（#info：あなた・座標・徳・照準など）を消す（?perf=1 等の計測用表示は残す）
12. 左下に自分の情報パネル。正方形くらい・画面の縦の約1/3まで使ってよい。上から：
    - 残りHP を大きく数字で
    - 悪行を紫系のバー
    - プレイヤー名
13. 指名手配中はパネルを四角く囲い、その上に「WANTED」の表記。左上のバフ欄の指名手配表示は今のまま
14. 右下のミニマップを、右上の顔パネル（みどり組の側）の下へ移す。ミニマップの長押し・右クリック長押しでの視点移動は今どおり
15. 右下の空いた所：技ボタンを今のミニマップくらいの大きさで置き、その上に照準と帰還のボタンを今の技ボタンより大きく置く
16. スロット（リール・保留）と左右の顔パネルを少しずつ大きくする（倍率は定数。仮置きで1.2倍）
17. ボタン・ミニマップはゲーム画面の中に置く（左右の余白には出さない）
18. スマホ（iPhone 横向き相当）と PC の両方で、ボタン同士・ミニマップ・パネル・キルログ・スロットが重ならないこと

## 4. 帰還ボタンの調査（直さない）
本人の報告：帰還ボタンを1回押しても反応が悪いことがある。Chat がコードを読んだ範囲の候補：
- 入力の順序：qdown（GameRoom.ts 195行）は届いた瞬間に溜めを始めるが、移動入力は p.inputs に積まれて1tickに1つずつ処理される。スティックを離してすぐ押すと、まだ処理されていない移動入力が後から setInput に渡り、cancelRecall（361行）で溜めが消える
- 自動の通常攻撃：射程内に敵が入ると attack() が cancelRecall（1268行）を呼ぶ
- 押し方：帰還は3秒（RECALL_HOLD）押し続ける仕様で、短く押すと qup で溜めを捨てる（199行）。押し続けているつもりでも指がずれて pointerup・pointercancel が来ていないか（main.ts 743行 btn('.rc')）

各候補が実際に起きているかを確かめる（溜めが始まった直後の中断を、中断の理由ごとに記録して数える。Bot戦や手動の操作、遅延を入れた状態で）。結果と直し方の案を報告して止める。修正は本人の判断後

## 成功基準
- 1：試合開始が決まってから3秒後に戦闘画面へ移る。戦闘画面に入った直後の数秒のフレーム時間（?perf=1）を前後で比べた表があり、悪くなっていない
- 2：CSV の全セリフが char_lines.md と vvproj にあり、話者の対応表が報告にある（音声は本人の調声後）
- 3：iPhone 横向き相当と PC のスクショ（通常・指名手配中・撤退中）で、指示どおりの配置で重なりがない
- 4：候補ごとに起きているか・頻度の記録、直し方の案がある
- 5・6：Bot戦のスクショ・数値で確認
- 7：選択画面のスクショ（iPhone 横向き相当と PC）で、2つのボタンが大きくなり重なりがない
- typecheck・test:server が通る。e2e は増やさない（既存の e2e が HUD の位置に依存して落ちる場合は、テスト側の位置だけ直してよい）
