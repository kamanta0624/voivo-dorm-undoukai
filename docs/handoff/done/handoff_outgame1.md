## 1. 開発環境と公開環境の分離
運用：開発フォルダで自由に触り、まとまったら一括で公開側へ反映する
1. 公開用フォルダを別に作る（git worktree、例 ~/kiritan_zunda_proto_live）。公開側は特定のコミット（タグ `live-YYYYMMDD-N`）に固定。node_modules・dist・logs は公開側に独立
2. 反映スクリプト `tools/deploy.sh <タグ>` 1本：
   - 試合中の部屋があれば中止（3章の /status で判定）
   - メンテ中にする（4章）→ 公開側を指定タグへ → 依存が変わっていれば npm ci → ビルド → ゲームサーバーだけ止めて同ポートで再起動 → メンテ解除
   - cloudflared は触らない。share.sh は使わない
   - 失敗時は直前のタグへ戻す手順を表示して止まる
3. 開発側の `npm run dev` は公開側と別ポートのまま
4. 現在の公開サーバー（開発フォルダから起動中）を公開側フォルダへ移す切り替えは、本人の指示を受けてから。手順（止めるPID・起動コマンド）を書いて止める
5. F（launchd）は公開側フォルダの起動を対象にする

## 2. タイトル画面と部屋選択
6. 入室前にタイトル画面（ランディング）。ゲームタイトル、自分の名前、部屋一覧、「ルール説明」ボタン（中身は別紙）、更新情報、クレジット、バージョン表示
7. 部屋は常設2つ（定数、仮置き2）。サーバー起動時に作り、空になっても破棄しない。試合後は待機に戻る
8. 部屋一覧に状態を表示：待機中（人数/上限）・対戦中・満員。手動更新でなく数秒ごとに自動更新
9. 入れるのは待機中かつ空きありの部屋だけ。対戦中・満員は押せない
10. 満員の定義：人間の参加者が4vs4の枠（8人）に達した状態（定数、仮置き）。観戦枠での入室はなくす
11. 再接続（RECONNECT_SEC）は対戦中でも従来どおり戻れる。e2e の部屋（?e2e=）は一覧に出さず、従来どおり動く
12. 部屋から出てタイトルへ戻る導線（待機画面・試合後）

## 3. プレイヤー名（自動・変更不可）
13. タイトル画面に来た時点でセッション（タブ）ごとにランダムな名前を付ける。本人は変更できない。名前の部品リストは設定ファイル1つ（中身は本人が後で直す。仮置きでよい）
14. 同じ部屋で重複したら末尾に番号
15. 表示は待機画面の組の一覧とタイトル画面だけ。キルログ・カットイン・実況には出さない
16. NGワード判定は不要

## 4. メンテ中表示
17. メンテ中フラグ（ファイル or 管理ページの切替。deploy.sh から操作できること）
18. メンテ中はタイトルに告知文を出し、入室を止める。進行中の試合はそのまま
19. /status：部屋ごとの状態・人数・メンテ中か、を返す（タイトルの一覧・deploy.sh 共用）

## 5. 旧版クライアントの自動リロード
20. 入室時（とタイトル表示時）にサーバーのビルドとクライアントの __BUILD__ を比べ、違えばリロード。無限リロードしないこと（1回だけ、それでも違えば「更新してください」表示）

## 6. 更新情報
21. 反映ごとの更新内容を1ファイル（例 public/patchnotes.md）に書く。タイトルに最新1件を出し、過去分は開いて読める
22. 文面は Code が反映時に下書きし、本人が直す。テストプレイヤー向けの言葉で（内部名・コミット名を書かない）

## 7. クレジット
23. タイトルからクレジット画面。VOICEVOX（使用キャラの「VOICEVOX:キャラ名」表記）、32dot素材、Moiky氏の立ち絵、その他使用素材
24. 表記の中身は README と各素材の規約から Code が一覧を作り、本人の確認を受けてから入れる（確認前は仮表示でよい）

## 8. publish1 から実施する分
- D（/admin・キック・BAN・解除・logs/bans.json）：参加者表示の「名前」は3章の自動名。メンテ切替もここに置く
- E（負荷試験）：部屋数は 1→2→4→8→12 のまま測る。上限の決定は本人
- F（launchd）：1章5のとおり公開側フォルダが対象。切り替えは本人の指示後

## 成功基準
- 別ポートで：タイトル表示→自動名が付く→2部屋の状態が見える→待機中に2ブラウザで同じ部屋に入れる→試合開始後は一覧で対戦中になり押せない→8人で満員→タブを変えると別の名前
- 試合中の切断→再接続で戻れる。e2e の部屋が一覧に出ない
- メンテ中に入室できず告知が出る。進行中の試合は止まらない
- ビルドを変えると旧クライアントが1回だけリロードされる
- deploy.sh を別ポート・別フォルダで試し、タグ指定で反映・メンテ切替・失敗時の戻し表示が動く
- verify/server.ts に追加：常設2部屋／対戦中・満員の入室拒否／BAN一致で拒否／/status の内容
- D・E・F は publish1 の成功基準どおり
- 既存の再接続・matches.jsonl・Bot戦が従来どおり。typecheck・test:server が通る。e2e は増やさない。スクショで報告
