## やること
推測で直さない。測って、重くなった変更を特定する。
1. 同じ場面（戦闘中。人間1＋Bot の4vs4、余白に立ち絵が出る画面の縦横比、スマホ 852×393 DPR3）を、perf5 の時点（live-20261125-12）と今（live-20261128-7）で測って比べる。WebKit（Playwright の webkit）でも測る（iPhone は WebKit。perf5 で、Chromium で効く直し方が WebKit で効かなかった例がある）
2. 測るもの：1フレームあたりの処理時間の内訳（スクリプト／スタイル再計算／レイアウト／描画）、WebGL の drawcall とテクスチャの転送量、DOM の書き換え回数とスタイル再計算の回数（毎秒）、画像のデコードの回数と大きさ、合成レイヤーの数。?perf=1 の今の計測で足りない分は、計測用にだけ足してよい
3. 差が出たら、その間のコミットを二分して、どの変更かまで絞る。perf5 より後にクライアントを触った主な変更（容疑の候補。順不同・これに限らない）：
   - tachie2（余白の立ち絵を身長比例で拡大、木箱の画像）・react1／react1b（出来事・タップで立ち絵の表情を差し替え＝大きい画像の読み込み・デコード）・screen1 後の中央寄せ
   - 0a0fcc3（マップに付く DOM を全画面の層 mapEl にまとめた）
   - ierutan3（アップグレードの発動エフェクト・光の柱）・hitbox1・shot1（通常攻撃の弾が射程×1.4まで飛ぶ＝同時に出る弾が増える）
   - font1（戦闘画面の文字 1.2 倍）・pwfx1／pwfx2・result1・hud2・nia1
4. 連戦で重くなるか（1試合目と3試合目の比較）も同じ測り方で見る

### まずやる計測
- MutationObserver（属性・子・文字の変更）を document 全体に付け、要素ごとの毎秒の変更回数を数える（計測用。?perf=1 の時だけ）。戦闘中に、立ち止まる／歩く／スロットの回転中／当選・罰の表示中／バフ・デバフ中 で分けて、毎フレーム書き換えている要素と書いている場所（関数）を特定する
- left/top・width/height・文字の書き換えは「値が変わった時だけ」「位置は transform」で済むはず。レイアウトを起こす書き換えを毎フレームしている所を一覧にする
- div.tk のペイントが増え続ける理由（何が描き直しを起こしているか）を特定する
