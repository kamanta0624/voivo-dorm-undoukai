# Code引き継ぎ：e2efix1（e2e・テストの揺らぎをなくす）

2026-11-25 Chat作成。不明点は勝手に判断せず本人に確認。範囲外のコード・コメントは変えない。

## 背景
11/24〜25 の反映のたびに、e2e が1〜2回落ちてから3回目で通る状態が続いている。落ちる項目は毎回違い、「今回の変更とは関係ない揺らぎ」として流してきた。このままだと本物の不具合を見逃す。
これまでに落ちた項目（各報告から）：
- 花丸：拳が出なかった確認、押し込みで壁が進まない確認（walldmg1 以降。自動チャージ・溜め・段階破壊と、テストの前提がずれている疑い）、矢印の角度（0.05rad 許容に 0.07rad）
- アル：タメ中の押し直し（テスト側でやり直しを入れたが残った回あり）
- 技ボタンを指で押す確認の瞬間に撃破されていた
- 開始カウントの秒数、裏側の資材の見た目、当選音、大将の拠点移動（自キャラが大将から約340px 離れていた理由は不明）
- サーバーテスト「名前の重複」（乱数で名前が重なる）、通信テスト「ワープしない」（Bot の動き次第）
- ファイルを変えた直後の1回目は vite の再読み込みで止まる（検知して止める仕組みは入れ済み）

## やること
1. 現状把握：何も変えずに e2e 全体を10回、サーバー・通信・実況のテストを各10回流し、落ちた項目・回数・落ちた時の状態（スクショ・ログ）を表にする
2. 項目ごとに原因を特定し、分類する：
   - (a) テストの書き方の問題（待ち方・前提・乱数・ほかの Bot や攻撃の割り込み）→ テスト側を直す
   - (b) ゲーム側の不具合（例：条件次第で技が出ない、壁が進まない）→ 直さずに報告して本人に確認（ゲームの仕様に関わるため）
   - (c) 環境（マシンの負荷など）→ 対策案を報告
3. (a) を直す。直し方の原則：
   - 固定時間の待ちを増やすのではなく、状態がそろうのを待つ（サーバーの状態・表示の完了を条件にする）
   - Bot・攻撃・スロットなどの割り込みで前提が崩れる項目は、e2e 用のフック（既存の e2eReady・e2eTeleport 等）でその確認の間だけ前提を固定する
   - 乱数で揺れるサーバーテストは、乱数を固定するか、揺れても成立する判定にする
   - 「1回だけやり直す」で隠すのは最後の手段。使う場合は理由を報告
4. ファイルを変えた直後は数秒待ってから流す（e2e の起動側で自動で待つ）
5. 直した後の確認は e2e 全体1回とサーバー系テスト1回だけ（2026-11-25 本人指示で変更。10回の再実行はしない）。原因不明の項目はログを残す仕掛けだけ入れ、普段の実行で落ちた時に調べる

## 成功基準
- 直した後の1回で、e2e・サーバー・通信・実況のテストが通る。原因不明で残る項目（例：そらの予兆）は、ログの仕掛けと次に落ちた時の調べ方を報告して完了とする
- e2e 1回あたりの所要時間を前後で報告（長くしない。本人は e2e が長いことを気にしている）

## 反映
テスト側だけの変更なら反映は不要（コミット・push のみ）。(b) でゲーム側を直すことになった場合は、本人の確認後、CLAUDE.md の運用どおり反映。完了後、本ファイルを docs/handoff/done/ へ移してコミット・push
