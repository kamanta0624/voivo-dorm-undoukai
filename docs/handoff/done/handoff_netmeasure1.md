## 背景（Chat の調査結果。コードからの見積もり、実測なし）
- 他キャラは NET_INTERP_DELAY（0.2秒）過去を補間して描き、自キャラは予測で先に描く。表示と判定の差は速度と遅延の両方に比例する
- 人間の近接AAは巻き戻し判定（lagcomp1）で殴る側に寄せている。殴られる側では「当たっていないように見えて当たる」が起こる。弾・技・Bot は巻き戻しなし
- 処理落ち・遅延の実際の原因（サーバーの tick 超過／クライアントの描画／通信の揺らぎ）は未計測
- 既存の計測: `?perf=1` は視界の計算時間とフレーム間隔だけ（描画処理全体の所要時間ではない）。tools/loadtest.ts は Bot 相当の模擬対戦での tick 処理時間・CPU・送信量。実対戦の遅延・揺らぎの記録はない
- 可変補間は有力候補。採否は本計測の後に判断する

## 1. 計測
記録する項目（クライアント単位）:
- RTT（往復遅延）。RTT だけでは片道遅延と時計差を分けられないので、時計合わせの offset（Interp.offset）とその変動も併せて記録する
- スナップショットの受信間隔（分布・最大）
- 補間の材料が足りなかった回数・時間（NET_EXTRAPOLATE による推測に入った回数、上限で止まった回数）
- 入力待ち: サーバー側の入力キューの長さ、NET_CATCHUP で追いつき処理した回数、NET_QUEUE_MAX で捨てた数
- 巻き戻し: 近接AAごとの「上限適用前の要求量」（elapsed − viewT）と「実際の巻き戻し量」の両方、上限 NET_REWIND_MAX に当たった割合
- クライアントのフレーム間隔（分布・最大）

記録する項目（試合単位・サーバー）:
- 1tick の処理時間（分布・最大）、tick の間隔（TICK_HZ に収まっているか）

記録の方法:
- 試合単位・クライアント単位で集計して、試合終了時に試合ログ（GameRoom.writeLog の JSON Lines）へ1回書く。毎フレーム・毎tick のログ書き込みはしない
- クライアントの集計値は試合終了時（または切断時）にサーバーへ1回送る
- 分布は固定のバケット（ヒストグラム）か、少数の分位点で持つ。生の値を溜め続けない
- 集計結果を読む簡単なスクリプトを tools/ に置く（試合ログから上の項目を一覧にする）

成功基準:
- 開発環境で、遅延・揺らぎを人工的に入れた条件（verify/net.ts の仕組みを流用してよい）で記録の値が設定どおりになることを確認するテストを追加して通る（例: 揺らぎ100msで受信間隔の分布が広がる、遅延を増やすと要求量が増え上限到達率が上がる）
- 計測による負荷増加を確認: 計測のオン・オフで tools/loadtest.ts の tick 処理時間を比べ、差を報告。クライアントは `?perf=1` のフレーム間隔で比べて報告
- 計測のオン・オフを config で切り替えられる（既定はオン。負荷が問題なら報告して判断を仰ぐ）

## 2. 巻き戻しの不連続の修正
現状: rewound()（GameRoom.ts 1001行付近）は前後の履歴を無条件に直線補間する。瞬間移動の前後で、実際には通っていない途中の位置に当たり判定ができる。

修正:
- 不連続は距離ではなくイベントで区別する（距離で判定すると高速移動を瞬間移動と誤認する）
- 不連続として扱うもの（候補）: 復活、リコール（帰還）、大将の拠点移動、アシストの出現
- 連続として扱う（今のまま補間する）もの: 通常移動、アルの突撃、はじき、ひまりの跳躍などの技の移動
- 上の候補以外に位置が飛ぶ処理があれば、勝手に分類せず一覧にして報告する
- 履歴に不連続の印を付け、境界をまたぐ時刻の巻き戻しでは、境界より前の時刻は移動前の位置、境界より後の時刻は移動後の位置を使う。途中の架空の位置は作らない

成功基準:
- verify に再現テストを追加して通る: 復活・リコール・大将の拠点移動のそれぞれで、境界をまたぐ巻き戻しが途中の位置で当たらないこと。突撃・はじきの高速移動は従来どおり補間されること
- 再現テスト（判定の変化の確認用）: 通常速度、加速の重複（あいえるたん＋白上＋パワーアップ近接）、追走、すれ違い、瞬間移動。高速移動中の接触判定のすり抜け（ビィの接触など）も再現を試み、起きるかどうかを報告（修正はしない）

## 3. 汗の位置合わせ
現状: 通常攻撃の汗（main.ts 599行付近の aaFx）はサーバー座標 f.x に描いている。

修正:
- サーバーの汗の fx に対象 ID を載せる
- 各クライアントは、その対象の表示位置（他キャラは補間位置、自キャラは予測位置）に汗を描く
- 対象が表示されていない（視界外・撃破済みなど）場合は汗を描かない
- 実装済みの点滅・ダメージ数値・着弾エフェクト（中・大）は変えない

成功基準:
- ブラウザで、加速中に逃げる相手を殴り、汗が相手の表示位置から出ているスクショ（殴る側・殴られる側の両方の画面）

## 実施結果（2026-11-21）

開発側のみ実施。公開側への反映なし。

### 計測とログ

- `CONFIG.NET_MEASURE` を追加。既定オン。サーバー起動時の `NET_MEASURE=0` でもオフにできる。設定は試合開始時に固定し、クライアントへ通知。
- 固定23バケット、件数・合計・最小・最大を保持。毎フレーム／毎tickの生データを蓄積しない。
- RTTは1秒ごとのecho。受信間隔、Interp.offset、offsetの前回差、実時刻差によるフレーム間隔を記録。
- 推測・上限停止は「対象ごとの状態遷移回数」と「対象ごとの描画時間の合計（entity-ms）」。同一フレームの複数参照を重複計上しない。
- 入力キュー長は処理直前の件数。catchupは2入力処理を選んだtick数。dropはキュー上限で捨てた入力数。
- 巻き戻しは人間の近接AA実行ごとに1計上。要求量と実適用量を別々に記録。上限率の分母は描画時刻を持つ近接AA数。
- 試合終了時にレポートを要求。クライアントは試合終了またはpagehide・明示的退出時に1回送信。サーバーは最大2秒収集して従来の試合ログ1行に `net` を追加。終了時刻は決着した時刻を維持。
- 突然の通信断や期限超過で届かなかった値は捏造せず `missingClients` に記録。全員退出による試合打ち切りは `kind=disconnect`。重複レポート・試合ID違い・不正な集計形式は不採用。
- 読み出し: `npx tsx tools/netmeasure.ts logs/matches.jsonl`。全項目、分布、上限率、欠損クライアントを表示。

### 記録の検証

`verify/netmeasure.ts` を `test:server` に追加。順序を保持する仮想通信路に人工遅延・揺らぎ・時計差5秒を投入。

| 条件（片道） | RTT平均 | 受信間隔の最小〜最大 | 巻き戻し要求平均 | 上限到達率 |
|---|---:|---:|---:|---:|
| 遅延50ms、揺らぎなし | 100ms | 50〜50ms | 300ms | 0% |
| 遅延100ms、揺らぎ±100ms | 250ms | 0〜210ms | 343.15ms | 46.07% |
| 遅延200ms、揺らぎなし | 400ms | 50〜50ms | 600ms | 100% |

揺らぎ条件のRTTには、順序保持による待ち時間と10ms刻みの配送が含まれる。実巻き戻し量は350ms以内。時計offsetは無揺らぎ条件で5050ms／5200ms。入力25件で5件破棄、処理直前20件、catchup 1回を確認。tickの時計を制御した検証で処理3ms・間隔50msを確認。

実ブラウザでも終了レポートがJSON Linesの1行に入ること、読み出しスクリプトで一覧化できること、欠損なしを確認。

### 不連続イベント

- 復活、リコール、大将の拠点移動、アシスト出現を記録。出現前のアシストは巻き戻し対象から除外。
- 追加発見分: `unstick` の単独壁補正、通常移動・突撃・跳躍・はじき・ビィのBot移動・コバコ移動の開始時の壁補正。本人回答に従い不連続扱い。
- `stepPlayer` 内の毎stepの壁補正は連続扱いのまま。
- E2E座標変更: 大将横への移動、任意座標への移動、アシストの隣接配置、コバコの隣接配置。不連続扱い。
- 開始演出の整列・終了時の集合は戦闘外。phaseの変更時に位置履歴と不連続履歴を消去。開始直後に履歴がまだない場合も検証。
- 場の物の追従座標（ビィのoverload等）は位置履歴の対象外。従来どおり現在位置を使う。場の物の壁補正が通常移動の巻き戻しを新設しないことも検証。
- 復活・帰還・大将移動で、境界前は移動前、境界時刻は移動後となり、遠距離移動の中点に誤命中しないことを確認。突撃・はじきは連続補間。通常速度・加速重複・追走・すれ違いも再現テスト通過。

既存の別件: `rewound()` は不連続がない履歴で要求時刻がサンプル時刻と完全一致すると、現在座標を返す。今回の許可範囲外のため変更なし。通常移動の回帰テストはサンプル間の時刻で実施。

### ビィの接触すり抜け

重複加速（あいえるたん、白上、近接パワーアップ、オーバードライブ）で速度758.472px/sのビィ同士を対向通過させた。接触距離50px。

- 50ms・1stepずつ: この配置では接触を取得。

- 50msでも入力待ち4件からcatchupで2stepずつ処理すると、1tickの相対移動151.6944px。交差後も接触予約なし。すり抜け再現。

修正なし。
