# Code引き継ぎ：perf3（悪化前の水準へ戻す：部分転送＋視界の頂点コピー削減）

2026-11-24 Chat作成。perf2 の報告（docs/handoff/done/handoff_perf2.md の結果）の案 C＋E を採る。不明点は勝手に判断せず本人に確認。範囲外のコード・コメントは変えない。見た目は1ピクセルも変えない。

## C. マップを1枚のテクスチャに戻し、壊れた範囲だけ部分転送
- perf1 の 512px 区画28枚をやめ、マップは1枚のテクスチャ（3104×2016）に戻す。作業用 canvas と区画の canvas の二重持ちもやめる（テクスチャの元 canvas を1枚だけ持つ）
- 壁破壊時は、今と同じく paintMap で周り±2マスを元 canvas に描き直し、その矩形だけを WebGL の texSubImage2D で GPU のテクスチャへ送る（1回約26KB）。Phaser の refresh()（全量転送）は初回とリセット時だけ
- Phaser を通さず WebGL を直接呼ぶので、次を必ず守り、確認結果を報告：
  - 呼ぶ前に Phaser の描画バッチを flush し、終わったらテクスチャのバインド状態を Phaser が把握している状態に戻す（Phaser 側の API があればそれを使う）。直後の描画が崩れないこと
  - pixelArt（NEAREST）・premultiplied alpha・flipY など、Phaser が最初に送った時と同じ設定で送る。境目に線やずれが出ないこと
  - WebGL のコンテキストロスト→復帰で、マップが壊れた状態のまま正しく戻ること（元 canvas から全量で復帰する）
  - 壁破壊が同じフレームに複数ある時は、矩形ごと（または合わせた矩形）でまとめて送る
- 成功基準：
  - perf2 と同条件で、GPU 転送が悪化前の水準（60秒で数MB）、drawcall が悪化前並み（4〜5回）、テクスチャ量が区画分の重複なし
  - 壁破壊の前後のマップ層の全面撮影が、今の版と画素一致（perf1 と同じ方法）
  - コンテキストロストの模擬（WEBGL_lose_context）で復帰後も一致

## E. 視界ポリゴンの頂点コピーと SVG の組み立てを必要な時だけに
- スロットのモダン演出のための「視界ポリゴンを毎フレーム画面座標へコピー」と「mfxArea の SVG 文字列の組み立て・比較」を、演出が出ている時だけ、かつ視界かカメラが変わった時だけにする
- 成功基準：演出が出ていない時の頂点コピーが0。演出の見え方は今と同じ（演出中のスクショ比較）。perf2 と同条件で視界の計測区間が悪化前との差 約+0.04ms（レイの長さの増加分＝仕様）まで縮む
