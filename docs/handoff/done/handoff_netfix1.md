# 引き継ぎ書: netfix1（ビィの接触のすり抜け修正＋rewound() の時刻一致の修正）

対象: ~/kiritan_zunda_proto（開発側）。公開側への反映はしない（本人の指示でまとめて tools/deploy.sh）。
前提: netmeasure1（コミット 5d9e273、docs/handoff/done/handoff_netmeasure1.md）の報告で見つかった2件。

## 1. ビィの接触のすり抜け
現状: bii.ts の update は、移動後の位置どうしの距離（体の中心どうし、t.r + B.touch 以内）だけで予約を判定する。netmeasure1 の再現で、高速の対向通過（約758px/秒どうし）と、50ms でも catchup で1tick に2歩まとめて動いたときに、交差したのに予約されないことを確認済み。

修正:
- 接触の判定を、そのtickの移動の前後の位置を使った判定にする。ビィと相手の両方が動くので、相対運動での最接近距離が t.r + B.touch 以内なら接触とする
- 移動の前の位置は、そのtickの移動処理の前のビィ・相手の位置（catchup で2歩動いた場合も、tick の最初の位置から最後の位置まで）
- tick の途中に瞬間移動（netmeasure1 の不連続イベント: 復活・リコール・大将の拠点移動・アシストの出現・単独の壁補正・E2E 座標変更）があった相手・ビィは、その tick は移動後の位置だけで判定する（瞬間移動の経路で接触を作らない）
- 壁の扱い、予約の条件（対象の種類・targetable・同じ敵は1回）、ダメージは変えない
- 停止中・低速の接触は今の判定と同じ結果になること

成功基準:
- netmeasure1 のすり抜け再現テスト（100ms・150ms の対向通過、50ms＋catchup の2歩処理）がすべて接触を取得する
- 瞬間移動をまたぐ tick では、移動前の位置と移動後の位置の間で接触ができない再現テストを追加して通る
- 通常速度・停止中の既存の接触テストの結果が変わらない

## 2. ほかの接触判定の洗い出し（報告のみ）
- ビィと同じく「移動後の位置どうしの距離」だけで判定している接触・当たり判定（動く体と動く体、または動く体と止まっている物）を一覧にする。例: めたんのドリル、小夜の舞、狐火、アルの突撃、アイテム・徳の取得など。候補はこれに限らない
- 各判定について、1tick の最大の相対移動量（catchup を含む）と判定の大きさを比べ、すり抜けが起こりうるかを報告する
- 修正はしない（修正の要否は本人が判断する）

## 3. rewound() の時刻一致
現状: rewound()（GameRoom.ts 1084行付近）は、不連続のない履歴で巻き戻し先の時刻が記録の時刻とぴったり一致すると、記録の位置ではなく現在の位置を返す。

修正:
- 巻き戻し先の時刻が記録の時刻と一致したら、その記録の位置を返す
- 巻き戻し先の時刻が最新の記録より後（今の tick の時刻を含む）なら、今までどおり現在の位置を返す

成功基準:
- 記録の時刻ぴったりへの巻き戻しで記録の位置が返るテストを追加して通る
- netmeasure1 で追加した不連続・通常移動の巻き戻しテストが引き続き通る

### 1・3の変更

- tickの移動処理前に、全プレイヤー・大将の体中心を保存。入力のcatchupによる2stepも、tickの最初から最後までの移動として扱う。
- ビィの予約はtick末尾に確定。`updateEnts` より後の壁補正、はじき、大将移動、アシスト出現も判定に反映。
- 相対座標を `q0 = 相手の始点 − ビィの始点`、`q1 = 相手の終点 − ビィの終点` とし、線分q0→q1と原点との最短距離を判定。接触半径は従来の `t.r + B.touch`。
- どちらかに不連続イベントがある場合、または始点がない新規出現の場合は終点同士だけを判定。印はtickごとに破棄。`elapsed` が増えない早送り・goldenでも前tickの印を持ち越さない。
- targetable、対象の種類、同じ相手への予約回数、体中心、壁の扱い、ダメージとポーズの時刻は維持。場の物だけを単体更新する既存検証では、始点がないため従来の終点判定を使う。
- `rewound()` は最古・中間・最新の記録時刻との完全一致で記録位置を返す。不連続後に同tickで通常移動した記録も、その記録位置を返す。最新記録より後は現在位置を返す。

### 2. ほかの接触・当たり判定の洗い出し（変更なし）

対象ソースは `src/server/GameRoom.ts`、`src/server/skills/*.ts`、`src/shared/chars.ts`、`src/shared/config.ts`、`src/shared/geom.ts`。以下はコードからの上界評価。各技の実対戦での再現を確認した一覧ではない。

#### 比較条件と上界

- サーバーは20Hzを指定するが、受け取る実dtを50msに固定・上限設定する処理はない。50msの数値を、遅延tickを含む全条件共通の最大値とは扱わない。
- 表はdt=50ms、通常のゲーム内で共存可能な最大加速、双方の人間のcatchupを含む。E2Eによる異なる自技の重複付与は除外。追加のはじき・瞬間移動は別記。
- 人間の移動は1step=50ms、1tick最大2step。通常移動速度vの上界を `D(v,dt) = v × max(dt, 0.1)` と置く。人間・Bot両方を覆う上界であり、通常の1stepでは半分になる。
- あいえるたん1.5倍 × 白上1.3倍 × 近接パワーアップ1.3倍。ビィ／小夜は自技1.6倍も加わり、最大758.472px/s。通常移動の1tick上界は50ms／100msで75.8472px、150msで113.7708px。
- ひまりの跳躍は948.09px/s、残り距離最大100px。catchupでは増えない。全キャラの移動上界は `P(dt) = max(D(758.472,dt), min(948.09×dt,100))`。P(50ms)=75.8472、P(100ms)=94.809、P(150ms)=113.7708px。
- 同時に逆向きへ動く組の相対移動上界は、両者の移動上界の和。異なるタイミングで順番に更新される判定でも、相手のtick内の移動履歴を調べない問題は残る。
- 通常プレイヤー半径10px、大将24px。ファンネルは半径6px。表の判定寸法は通常プレイヤー相手。半径は直径と混同せず比較した。
- 相対移動が直径・幅を上回れば中央を丸ごと飛び越せる配置がある。下回っても端をかすめる短い弦や細い部分は飛ばせる。寸法未満だけで「安全」とは判定しない。

#### はじき・瞬間移動・壁

- 上表は追加の強制移動を含まない。WhiteCULは1回80px、めたんは1回40px、リツは1回60pxを `push()` で即時移動させる。1tickに複数命中すれば加算され、上表の速度だけから算出した上界を超える。距離は壁で短くなる。
- 任意のdt・はじき・不連続まで含めた全条件の固定最大値を、50msの数値として示すことはできない。比較式は各対象の `D(v,dt)` または技の移動式に、そのtickに実行されたはじき距離の合計を加える形。瞬間移動はその経路上の物理接触と区別する必要がある。
- 壁との移動衝突は `moveBody()` が最大4px刻みで処理。通常プレイヤー半径10px・タイル16pxに対し、上表の75.847pxを壁判定なしで一括移動しているわけではない。壁への埋まり補正は別の不連続イベント。
