# Code引き継ぎ：vision1（視界の全体短縮）

2026-11-24 Chat作成。不明点は勝手に判断せず本人に確認。範囲外のコード・コメントは変えない。

## 狙い（本人）
視界共有で今の視界は広すぎる（バランス）。あわせて、画面（論理 640×360）に対して視界が大きく、視界に入っていても画面外で見切れる（特にスマホで不利に感じる）。軽量化（視界計算はレイの長さにほぼ比例）にもなる。

## 仕様
- 視界の円は今のまま（向き・カメラは変えない）。半径だけ全体を同じ率で短くする
- 率：標準的な視界のキャラ（stat.vision 300・C.VISION_RADIUS 300）が画面の縦幅に収まる程度＝半径 180（VIEW_H/2）。率 0.6 を設定値（例 C.VISION_SCALE）1か所で持ち、全キャラ・大将の視界に掛ける（390 のキャラは 234）。各キャラの stat.vision の数値は書き換えず、率で掛ける
- サーバー（GameRoom の視界判定・情報の出し分け）とクライアント（視界ポリゴン・フォグ）で必ず同じ値を使う。shared/chars.ts の visionRadius に掛けるのが候補。eyeRadius（撃破後の縮み）も整合させる
- 後ろを短くする案・向きで変える案・カメラをずらす案は今回やらない（アイデアとして保留）

## 視界の値を使っている他の箇所（洗い出して、追従させるべきか判断して報告）
- 実況の battleR（config.ts 321行付近、VISION_RADIUS 前提）
- スロットの演出範囲（config.ts 241行付近の「視界は画面中央・半径 VISION_RADIUS の円」、slot_modern_fx.ts・slot_page.ts）：視界外の空き領域が広がる。追従させるのが筋だが、演出の配置が変わるならスクショを付けて本人に確認
- Bot の索敵・照準、選択画面のステータス表示（視界の棒があれば率を掛けた値で）
- そのほか VISION_RADIUS・visionRadius・stat.vision の参照すべて

## 影響の報告（直さない、列挙だけ）
- 技・通常攻撃の射程が新しい視界半径を超えるもの（例：ずん子のずんだアロー 300、そらのビーム、花丸パンチ 520、ユーレイ 320、アル突撃）。見えない敵に対する自動照準・矢印の初期向きがどうなるか

## 成功基準
- 標準キャラの視界の円が画面の縦にほぼ収まる（スクショ）
- サーバーとクライアントで見え方が一致（見えている敵の情報が来ない・見えていない敵が映る、が起きない）
- 視界の計算とフォグの塗りが下がる（計測は perf2〜perf4 と同じハーネス（ヘッドレス Chrome・CPU 4x・Bot 入り試合60秒×2回）で、?perf=1 の値・GPU 転送量・drawcall・メインスレッド時間を前後で比べる（docs/render_policy.md の7））
- e2e が通る（視界半径に依存する既存テストは新しい値に合わせる）
