# 引き継ぎ：実況機能（No.7）

## 目的
スーファミ・PSのパワプロ程度の実況を付ける。試合の出来事に合わせて、実況（VOICEVOX：No.7）が短いセリフを音声＋字幕で流す。戦闘の実況の作り込みがゲームの価値を左右する。「セリフを垂れ流しているだけ」にならないよう、注目度とフォーカスの仕組みで「いま誰を見ているか」を持たせる。解説役は今回入れない（追加しやすさのための抽象化はしない）。容量と処理負荷は小さく抑える。

## 仕様の正
`docs/commentary_spec.md`（台本＋判定ルール）。0章〜6章をすべて実装する。文言・優先順・読みを勝手に変えない。末尾の「未確定」は実装せず、着手前または完了時に確認する。

## 実況の視点
- 中立の全体視点（TV中継）。実況はマップ全体を見ている。全員に同じ実況を流す。チーム別の実況は作らない
- 戦闘の人数・状況、場所名を言ってよい
- チームは組の色で呼ぶ（みどり組・だいだい組など。対応は定数1か所）。コード内の陣営キー（kiritan/zundamon）や TEAM_NAME は変えない

## 構成
- 判定はすべてサーバー（GameRoom 側）の「実況ディレクター」1か所で行う（注目度・フォーカス・戦闘・個別プレー・平時の話題・割り込み）。マップ全体の情報が要るため
- サーバーは喋る内容だけを小さなメッセージ（イベントキー＋パターン選択に要るキャラ・組・技・場所・数のID）として全員に送る。座標は送らない。既存の 'kill' 'slot' 'assist' 'assistUp' 'penalty' などの送信は変えない
- クライアントは受け取ったメッセージの再生・字幕表示だけを行う（キュー・割り込み・破棄はクライアント側）
- ディレクターは出来事（damagePlayer・撃破・反省中／復活・技の発動と終了・召喚・コバコ被弾・大将の被ダメと拠点移動・スロットの各段階・視界への初登場など）のフックで状態を更新する。時間で動くもの（注目度の減衰、戦闘終了、平時の話題、追跡判定）は1秒（仮）に1回の軽い更新でまとめて処理する。毎tick（20Hz）の全キャラ走査はしない
- 大将接近・視界への初登場は既存の visibleTo（大将も視界の発生源）で判定する
- 進行中の戦闘は複数同時にありうる。戦闘ごとに状態を持つ
- 判定ロジック（注目度・フォーカス遷移・戦闘分類・一言の優先順・まとめ・平時の話題選び・回避判定）は純粋関数に切り出す
- 数値（注目度の値・閾値・減衰、半径、秒数、各閾値、間隔、クールタイム）は config.ts に1か所でまとめる
- 統計（キル数・連続撃破数・徳の獲得量など）が既存にない場合は、イベントフックでの加算だけで持つ
- 場所名：map.json の部屋の一覧（L/R、名前のない部屋・廊下を含む）を洗い出して報告する。読みは本人が決めるので、仮の読みで実装し差し替え可能にする
- 小ネタは台本ファイルに空の枠だけ用意し、空のキャラは選ばない

## 音（今は音を鳴らす仕組みがない）
- 実況用の再生を新しく作る（WebAudio）。同時1本
- iOS Safari 等の自動再生制限: 最初のタップ／クリックで音声を有効化する
- 実況のオン・オフ切り替えを新しく作る（音声と字幕をまとめて切る。端末に保存）。置き場所は着手前に確認
- 字幕：画面下部中央（右下のミニマップ・ボタン群と重ならない位置）、再生中だけ表示。PC・スマホ共通

## 方式（パワプロ式の分割再生）
- セリフは「定型文」と「部品（名前・組・技・場所・数）」に分け、事前に音声化して連結再生する
- 実行時のTTSはしない
- 話者はNo.7、スタイル「アナウンス」（スタイルIDは定数1か所）
- 台本はリポジトリ内の台本ファイル（イベントキー→パターン、部品一覧、技の読み）1つに落とし込む
- 字幕の名前類（キャラ名・技名・助っ人名）はハードコードせず、実行時に定義（chars.json・chars.ts の skill.name・config の ASSIST.units[key].name）を参照する。技名などを変えたら字幕は自動で追従する。台本の読みはキャラkey等で引く
- 音声生成時に、読みを作った時点の技名等を台本に記録し、現在の定義と食い違っていたら生成スクリプトが警告を出す（読みの更新漏れ防止）
- ランダム選択、直前と同じパターンは避ける

## 音声の生成（VOICEVOXプロジェクトを正とする）
本人がVOICEVOXエディタで調声し、その結果をゲームに反映できるようにする。
1. 台本→vvproj：台本ファイルから VOICEVOX プロジェクトファイル（.vvproj）を1つ生成する。部品1つ＝トーク1項目。既存のvvprojがあれば、文言が同じ項目は調声済みのクエリを残し、増えた・変わった項目だけエンジン（localhost:50021）でクエリを作って足す。台本から消えた項目は削除する
2. 本人がVOICEVOXエディタでvvprojを開き、調声して上書き保存する（手動）
3. vvproj→音声：vvprojの各項目のクエリ（調声結果）をそのままエンジンの合成に渡して音声化し、スプライトを作る。エディタからの書き出し作業は不要にする
- VOICEVOXのインストール有無・バージョン・vvprojの形式は、実機で確認して合わせる（推測で組まない）。生成したvvprojがエディタで開けること
- vvprojと台本ファイルはgit管理する（生成した音声も含めてよい）
- `npm run` のスクリプトとして登録する（例：生成・音声化の2つ）

## 軽量化
- 同じ文言の部品は1つにまとめ、使い回す
- 合成時に前後の無音を削る
- モノラル・低サンプルレート・低ビットレートで圧縮する。iOS Safariを含む全対象ブラウザで再生できる形式にする
- 全クリップを1ファイルのオーディオスプライト＋オフセット表にまとめる（リクエスト1回・デコード1回）
- 読み込みはゲーム起動を遅らせない形（試合前のロード中など）。失敗しても試合は進む（実況なしで続行）
- 音声ファイルの合計は1MBを超えてもよい（小ネタ追加分を含む）。サイズは報告する

## 再生のルール
- 優先度：決着 ＞ 全員反省中 ＞ 6章の全体（大将HP・拠点移動・スロット・優劣逆転） ＞ フォーカス中の撃破・まとめ ＞ 前置き・接敵・合流・連続・盤面 ＞ 個別プレー・追跡 ＞ 進行（形勢・残り時間） ＞ 平時の話題・小ネタ。高優先度は低優先度の再生を打ち切って割り込む
- 前置きと続くセリフは1つの発話として扱い、間で割り込まれた場合は続くセリフも捨てる
- 発生から2秒以上待たされたセリフは捨てる（撃破は1秒保留の後、まとめは戦闘終了を発生時刻とする）
- 試合前のセリフはロード完了時に流し、試合開始のセリフより前に終わらなければ打ち切る
- 形勢・残り時間は既存のカットイン（SITUATION_AT・END_WARN_AT）と同じタイミング・同じ判定で喋る

## クレジット
- ゲーム内クレジット（なければREADME）に「VOICEVOX:No.7」を記載する

## 成功基準
- `docs/commentary_spec.md` の全表の全行が、判定関数の単体テストで条件どおりのイベントキーになる（注目度の加算・減衰、フォーカスの開始・解除・移動の閾値と差、一言の優先順、まとめの優先順、回避判定、大将接近が大将側に見えたときだけ判定されること、パワーアップ中の撃破・罰による撃破を撃破として扱わないこと、平時の話題の回し方を含む）。テストは verify/ の既存の流儀に合わせる
- Bot戦の1試合で、実況ログ（時刻・フォーカス対象・注目度・イベントキー）を出力できる。そのログで、フォーカスが出来事の起きた場所を追って移り、移るときに前置きが入り、何も起きていない時間に平時の話題が流れていることを確認できる
- 実際の試合で音声と字幕が出る（PC・iOS Safariを含むスマホ）。両チームのプレイヤーに同じ実況が流れる。オフにすると音声も字幕も出ない
- 正しいキャラ名・組・技（読み）・場所・数が連結再生される。部品と定型文のつなぎが聞き取れる
- chars.ts の技名を1つ書き換えると、コード・台本の他の変更なしに字幕の技名が変わる。音声生成スクリプトはその食い違いを警告する
- 決着時は他の実況を打ち切って必ず流れる。古いセリフがまとめて遅れて流れることがない
- 実況のために座標がクライアントへ送られていない。サーバーの1tickあたりの処理時間を実況導入前後で計測して報告する
- 生成したvvprojがVOICEVOXエディタで開け、全部品が並んでいる
- エディタで1項目の抑揚を変えて保存→音声生成コマンド→ゲーム内のその部品に変更が反映される
- 台本の1行を変えて再生成しても、他の項目の調声が消えない
- 音声はスプライト1ファイルで、合計サイズを報告する
- 音声の読み込みに失敗しても試合が進行する
- `npm run typecheck`・`npm run test:server`・golden が通る（golden のハッシュが実況の追加で変わるなら理由を報告）
- `npm run share` で友人テスト公開が従来どおり動く（確認は別ポートで行い、稼働中のサーバーは使わない）

## 報告すること
- map.json の場所名一覧（L/R・名前のない部屋・廊下を含む、仮の読みつき）
- 実況オン・オフの置き場所の案（着手前）
- 実装できなかった出来事とその理由
- 音声の合計サイズ、サーバー処理時間の前後比較

## 守ること
- 稼働中のnpmサーバー（npm run share / dev）は止めない・再起動しない。検証は GAME_PORT・CLIENT_PORT で別ポートに別プロセスを立て、終わったらそのプロセスだけ止める
- 不明点は勝手に決めず、確認する
- 最小限のコード。投機的実装・不要な抽象化はしない（解説役の枠を先回りで作らない）
- 指示範囲外のコード・コメントは変えない
- e2eテストを増やさない
- `npm run share`、1ポート配信、接続先決定、cloudflared周りには手を入れない
