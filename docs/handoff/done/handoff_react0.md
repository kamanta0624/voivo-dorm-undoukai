## 目的（本人）
右余白の立ち絵（自キャラ）に、タップとゲーム内の出来事で、表情の変化とセリフ（吹き出し）の反応を付けたい。実装の引き継ぎ書（react1）は、この報告を見て Chat が作る。

## 本人の決定（2026-11-26）
- タップ：頭・顔・上半身・下半身で、表情とセリフを変える
- 出来事：キルを取る→笑う／やられる→悲しむ／残りHPが少ない状態で帰還→ほっとする／出会い頭にやられる→驚く／同じキャラに（繰り返し）やられる→怒る／大将に攻撃→喜ぶ
- セリフは吹き出し（字幕）のみ。音声は付けない
- 素材（Moiky 氏の立ち絵）は一切加工しない（レイヤー位置のずらしも含む）。使うのは既にある差分の絵の差し替えだけ
- 立ち絵の余白が無い画面（スマホ縦など）では何も出なくてよい

## 調べること
1. **素材**：Moiky 立ち絵のキャラごとに、使えるファイル（表情・ポーズの差分）を全部列挙する（MOIKY_DIR、tools/import_tachie.py と src/shared/chars.json が参考）。
   - 表：キャラ／ファイル名／PNG のサイズ／現在 select・ko・koed に使っているか
   - 差分ごとに、通常（select）と同じキャンバス・同じ位置で重ねられる（差し替えられる）か。絵の大きさ・不透明範囲が通常と一致するか
   - ファイル名から読める表情（笑・喜・驚・怒・悲・安心・照れ など）を並べ、上の出来事6つと、頭・顔・上半身・下半身の反応に当てられる候補を示す。足りないものは足りないと書く
2. **余白の立ち絵**（main.ts の余白の表示、sideFit・measureOpaque の付近）：今タップを受けられる状態か（pointer-events、入力の邪魔にならないか）。PC・スマホ別。観戦者・自キャラが無い時に立ち絵が出るか
3. **既存の通知で足りるか**：キルした（ko）、やられた（koed）、大将への与ダメ、リコール成功（帰還）、HP の割合、同じキャラに何回やられたか。足りないものと、足す場合の最小の足し方（サーバー→本人への項目追加の案）。「出会い頭」（見えていなかった敵に短時間でやられた）の判定に使える情報がサーバーにあるか
4. **吹き出しの置き場所の案**：余白の幅の実測、はみ出さない、ゲーム画面の入力領域を覆わない
