# Code引き継ぎ：友人テスト公開（段階1：自宅Mac＋Cloudflare一時トンネル）
対象：~/kiritan_zunda_proto
前提：handoff_tuning2.md 実装済み
目的：Discordの友人にURLを渡し、別回線のブラウザから同じ試合に参加できる状態にする。費用0円

## 成功基準
### A. 1ポート配信
1. `npm run share` 1コマンドで：クライアントの本番ビルド → サーバ起動（ビルド済みクライアントの静的配信とColyseusを同一ポートで）→ `cloudflared tunnel --url http://localhost:<port>` 起動 → 発行されたURLをターミナルに表示
2. クライアントの接続先はページのoriginから決める（https→wss、http→ws）。localhostの直書きをなくす
3. 既存の開発用コマンド（npm run dev等）の挙動は変えない
4. cloudflared未インストール時は、`brew install cloudflared` を案内するメッセージを出して終了

### B. 複数人参加
5. 別のブラウザ・別回線から同じURLを開いた2人以上が、同じ待機画面に入り、陣営とキャラを選んで同じ試合を開始できる
6. 人が入らなかった枠は従来どおりBot

### C. 再接続
7. 試合中にタブを再読込・回線が瞬断しても、一定秒数（定数、初期値30秒）以内なら同じキャラで復帰
8. 猶予を過ぎたらそのキャラはBotが引き継ぐ

### D. バージョン表示
9. 画面隅にビルドの識別子（gitの短縮ハッシュ＋ビルド日時）を小さく常時表示

### E. 試合ログ
10. 試合終了ごとに `logs/matches.jsonl` に1行追記：開始・終了時刻、試合時間、勝利陣営、決着の種類、陣営ごとのキャラと人/Botの別、大将に与えたダメージ（プレイヤー／アシスト）
11. `logs/` をgitignoreに追加

### 検証
12. `npm run share` で発行されたURLを、Mac本体のブラウザとスマホ回線（Wi-Fiオフ）の別端末で開き、2人＋Botで1試合を最後まで完走。スクショでバージョン表示を確認
13. 試合中に片方のタブを再読込して復帰すること、30秒超の切断でBotが引き継ぐことを確認
14. 完走した試合が matches.jsonl に1行記録されている
15. 既存Bot対戦が最後まで動く。verify/server.ts・e2e.ts が通る

## 不明なら止めて聞く
- 現行の待機画面・ルーム構成が複数人の参加を想定しておらず、大きな改修が必要な場合
- 再接続（C）が現行の状態同期の作りに乗らず、大きな改修が必要な場合（Cを外してA・B・D・Eだけ先に完了でも可）

## 禁止
範囲外の変更、不要な抽象化、ゲーム仕様の変更
