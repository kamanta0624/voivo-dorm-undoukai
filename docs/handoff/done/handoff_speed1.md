# 引き継ぎ書: speed1（極端な高速を抑える: ロール補正の焼き込み・速度倍率の引き下げ・あいえるたんの技を「アップグレード」に）

対象: ~/kiritan_zunda_proto（開発側）。公開側への反映はしない（本人の指示でまとめて tools/deploy.sh）。

## 背景
- 表示と判定の差は速度×遅延に比例する。加速の重ね掛けで最高約758px/秒まで出ていた（netmeasure1・netfix1 の報告）
- 速度を上げる倍率を減らし、極端な高速を出にくくする。速度以外のバランス（HP・攻撃・視界）は変えない

## 1. ロールのステータス補正をやめ、各キャラの数値に焼き込む
- 廃止: config.ts の ROLES の hp・speed・atk・vision の倍率、MELEE_BONUS（近接補正）。chars.ts の charHp・charSpeed・charAtk・visionRadius の計算をキャラ自身の数値を使う形にする
- 残す: ロールそのもの（role）と、ロール固有の効果（BALANCE_ALONE_CUT・DEFENSE_CUT・ATTACKER_BOSS_MULT）。選択画面の色分けなど role を参照する所も今のまま
- キャラごとの数値（HP・攻撃は今と同じ値、速度は下の変更後の値）:

| キャラ | HP | 攻撃（通常攻撃の基本値） | 速度(px/秒) | 視界 |
|---|---|---|---|---|
| hanamaru・itako | 120 | 24 | 170（今187） | 300 |
| whitecul・aru | 96 | 19.2 | 187（今243.1） | 390 |

- アシストの HP・攻撃・速度は今の計算（基本値×アシストの倍率）のまま。GameRoom.ts 1173行付近でアシストの攻撃に roleOf(p.char)?.atk を掛けている所は、結果の値が変わらないように扱う
- 数値の置き場所は Code に任せる（chars.ts の各キャラの定義に持たせるのが自然）。置き方で迷ったら質問

成功基準:
- 上の表の値が、サーバーの maxHp・speedOf・attack と選択画面のステータス表示に出る（テストで全キャラを確認）
- アシストの HP・攻撃・速度が変更前と同じ（テストで確認）

## 2. 速度の倍率の引き下げ
- 白上虎太郎（アシスト）の加速 boost: 1.3 → 1.1
- パワーアップ近接（ULT_FORMS.melee）の speed: 1.3 → 1.1

## 3. あいえるたんの技: 加速 → アップグレード
- 技名「アップグレード」（実況の読みは「あっぷぐれーど」）
- 対象・時間・回復は今のまま: 自分と半径 r（150px）内の味方、dur（5秒）、効果中は毎秒 regen（3）回復
- 移動速度の上昇（speed 1.5）は廃止。代わりに通常攻撃のクールタイムを 0.8 倍にする
  - 近接・遠距離の通常攻撃の両方に掛ける
  - パワーアップ中の通常攻撃（GameRoom.ts 1160行付近の固定値）にも掛ける
  - アシストには掛けない（アシストが範囲内にいた場合の回復は今のまま）
- 表記をすべて変える: 技名の定義（chars.ts の skill.name）、選択画面の説明文（desc）、バフ欄の表示（main.ts 44行付近は技名定義を参照）、実況台本（commentary_script.json の ierutan の技名と読み）。技名の音声部品は既存の手順で作り直す
- 状態の key（accel）を変えるかは Code に任せる。変える場合は参照箇所すべて（クライアントの描画・色・本人画面の範囲表示を含む）
- Bot の使用判断（敵が近いとき）は今のまま
- docs/char_catalog.md と .claude/skills/char の記載も今回の変更に合わせて更新する（キャラ追加・修正ごとに更新する方針）

成功基準:
- アップグレード中の味方の近接・遠距離・パワーアップ中の通常攻撃の間隔が 0.8 倍になり、移動速度は変わらない（テストで確認）
- アシストの通常攻撃の間隔は変わらない（テストで確認）
- 「加速」の表記がゲーム内・実況に残っていない（白上の「加速（アシスト）」は別物なので残す）

## 共通の成功基準
- 1章の HP・攻撃・視界の値は変更前と完全一致（バランスを変えるのは速度とアップグレードだけ）
- 変更後の最高速度の確認: 加速の重なり（白上1.1×パワーアップ近接1.1）で、スピード役の通常移動 約226px/秒、小夜・ビィの技中 約329px/秒になることをテストで確認
- Bot 同士の試合結果（golden）は速度の変更で変わる。どの試合で何が変わったかの要約を報告してから golden を更新する
- npm run typecheck・test:server が通る
