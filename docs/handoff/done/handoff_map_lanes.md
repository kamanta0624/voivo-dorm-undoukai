## 設計意図（判断基準）
- 中央の衝突エリアは3つ：トップ25・ミッド26・ボット27
- 開始地点 11/12 からトップ・ミッド・ボット・裏のどこへもすぐ行ける
- トップとミッドはほぼ繋がり徳を稼ぎやすい＝基本の激戦区。大将の位置で変わる
- ボットは徳は少ないがコバコが出る。ミッド裏取りの経路としてたまに戦闘
- 裏＝11/12と中央以外の全部。広く、巡回が必要で、侵入者に気づきにくい
- 回復は給湯室のご飯だけ。いくらでも回復できるが、食べるたびに徳が減る（既存の「盗み食い」）
- MOBA風だがレーンにこだわらない。イベント高密度

## 成功基準
### マップ
1. 開始部屋（START_ROOMS）を study → dining（11/12）に変更
2. 3 annexN と 7 parlor を連続した1部屋（図書室）に統合（左右とも）。形は案をスクショで報告し、承認後に確定
3. 7 と 8 を結ぶ通路を新設。途中で 25 smoking の上辺に出入口を持つ
4. 部屋の設定名を map.json の rooms に持たせる（表示に使うかは後で決める）
5. gen_map.py の検証（左右対称・全部屋到達）が通る

### ルール
6. リコール先（RECALL_ROOMS）を annexN → kitchen（13/14）に変更
7. 撃破後の復活地点は study（1/2）
8. 大将の出現・逃亡先候補（BOSS_ROOM_CANDIDATES）から dining を除外。仕組み（選ばれた3部屋を被ダメで移動）は既存のまま
9. 自陣回復（BASE_REGEN、study＋annexN にいる間の回復）を廃止
10. 回復アイテム（ご飯）：
    - 出現場所（HEAL_SPOTS）を kitchen（13/14）だけにし、複数個置く
    - 取られても短時間で再出現し、実質いくらでも食べられる
    - 1個ごとに既存の TOKU.eat（盗み食い）で徳が減る
    - 個数・再出現秒数は定数
11. Bot：自陣回復の廃止に合わせ、HP低下時はリコール→給湯室で食べる動きにする
