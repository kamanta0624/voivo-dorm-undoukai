# 引き継ぎ：友人テストの反映（通常攻撃・ミニマップ・撃破表示・徳・コバコ）（~/kiritan_zunda_proto）

## 目的
「通常攻撃が機能していない」などの意見に対応する。攻撃が見て分かる、操作に無駄なボタンがない、撃破の理由が分かる、コバコの巡回に意味がある状態にする。

## 作業
### 1. 通常攻撃（AA）を見えるようにする
- 近接AAに斬撃エフェクトを出す（攻撃者の向き・射程に合わせる）
- AAが当たった側に汗のエフェクトを出す（近接・遠距離とも）
- エフェクトは別スプライト・別レイヤーで重ねる。32dot素材・立ち絵は加工しない

### 2. 攻撃ボタン・攻撃キーを廃止し、AA固定にする
- 通常攻撃は常にAA。スマホの攻撃ボタン、PCの攻撃キーをどちらも廃止する
- 対象モード切替は残す
- 対象モードに「コバコ」を追加する。このモードではコバコも攻撃対象になる（ほかのモードではコバコを狙わない）
- コバコを攻撃したときの徳の減少（既存のコバコ襲撃）はそのまま

### 3. UIをPC・スマホで統一し、ミニマップで視点を動かす
- 画面構成はPC・スマホ共通。右下にミニマップ、その上に技ボタン・対象モード切替ボタン・リコールボタン。PCでもこのボタンを表示する
- スマホ：ミニマップに触れている間、触れた位置へカメラを移す（指を動かせば追従）。指を離すと即座に自キャラ視点へ戻す
- PC：ボタンはマウスでクリックできるようにする。ミニマップの任意の位置を右クリック長押ししている間、その位置へカメラを移し、離すと即座に自キャラ視点へ戻す
- PCのキーボード操作（攻撃キー以外）は残す。既存の操作感を変えない
- 視点移動中もキャラ操作・技は効くこと。視界（チーム共有）の判定は変えない（カメラが動くだけ）

### 4. アイテムの取得判定を広げる
- 取得判定をキャラの当たり判定から分け、全キャラ共通の縦長長方形にする（頭・上半身まで含む）
- 低身長キャラが不利にならないよう、サイズはキャラによらず一定。定数1か所で調整できるようにする

### 5. 撃破の表示
- 撃破されたとき：誰に何で倒されたか（AA／技名）を大きく表示し、ラストヒットを取ったキャラの立ち絵（KOした時の表情）を出す。既存の被KOカットイン・復活待ち時間の表示と共存させる
- 撃破したとき：既存のKOカットインに、誰をどうやって（AA／技名）倒したかを表示する
- 立ち絵と表情は impl_policy.md の対応表に従う

### 6. 徳アイテム
- 徳アイテムの出現頻度を現在の2倍にする
- 取得時のフレーバーテキスト（「ゴミを捨てた」など）を消し、「徳+XX」の表示だけにする

### 7. コバコの巡回
- コバコが部屋に入るたび、30%の確率でその部屋に高性能の徳アイテムを1つ置く。確率は定数にする（30%は仮置き）
- 1部屋あたりの上限なし。未取得の高性能の徳が残っていても、当たれば追加で置く。置き場所は既存のアイテムと重ならない位置にする
- 高性能の徳の上昇量は、陣内に湧く通常の徳アイテムの2倍
- 回復部屋の回復アイテムを上限2つに減らし、効果を2倍にする
- 回復アイテムは消費しても自動では補充しない。コバコが回復部屋に到着したとき、上限2つまで補充する

## 成功基準
- 近接AAの斬撃と被弾側の汗が、PC・スマホのどちらでも目で見て分かる
- PC・スマホとも攻撃ボタン・攻撃キーがなく、AAが自動で出る。対象モード「コバコ」でコバコを攻撃し、それ以外のモードでは攻撃しない
- PCとスマホで同じボタン配置になっている。PCではマウスでボタンを操作できる
- スマホでミニマップを触っている間だけ視点が飛び、離すと即戻る。PCでは右クリック長押しで同じ動作。攻撃キー以外のキーボード操作は従来どおり
- 低身長キャラと高身長キャラで、同じ位置関係ならアイテムの取得可否が同じ
- 撃破時・被撃破時に、相手・手段（AA／技名）・立ち絵が表示される
- 徳アイテムの出現頻度が2倍、表示は「徳+XX」のみ
- コバコが入った部屋に30%の確率で高性能の徳（通常の2倍）が置かれ、複数置かれても重ならない
- 回復部屋の回復アイテムが上限2つ・効果2倍で、コバコ到着時だけ上限まで補充される
- 既存の単体テストが通る（攻撃キー廃止に伴うテスト修正は可）
- 友人テスト公開（handoff_friend_test.md）が壊れていない：`npm run share` でCloudflareトンネル経由のURLが発行され、別回線の端末から参加して1試合完走できる。再接続・バージョン表示・matches.jsonl も従来どおり動く

## 守ること
- 不明点は勝手に決めず、確認する
- 最小限のコードにする。投機的な実装や不要な抽象化はしない
- 指示の範囲外のコード・コメントは変えない
- 素材（32dot・立ち絵）は加工しない
- e2eテストを増やさない
- 頻度・確率・効果量・判定サイズなどの数値は定数1か所にまとめる
- `npm run share`、1ポート配信、originから決める接続先（https→wss）、cloudflared周りのスクリプト・設定には手を入れない
