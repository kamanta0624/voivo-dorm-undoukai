## 成功基準
- npm run dev のゲーム画面で、0・1章の間取り・床・壁・家具が出る。左右対称。壁破壊後も見た目が崩れない
- 縮めたアトリウムへ南廊下から入れる。旧アトリウムの空いた所には入れない。ガラス・柵越しに視界が通り、移動・攻撃・弾は遮られる
- 素材が git に入っていない（git status・git ls-files で確認）。素材がない状態で起動してもエラーで止まらず分かる表示が出る
- 実況で新しい場所名が音声・字幕とも出る（Bot 戦で確認）
- typecheck・test:server が通る。golden が変わるなら理由を報告。e2e は増やさない（既存は通す。間取り変更で壊れた既存の項目だけ直す）
- スマホ相当の画面（DevTools）で処理落ちが目立たない
- 報告：スクショ（全体、道場・茶室・弓道場・窯小屋の近く・アトリウムと伸ばした廊下、各床系統のアップ、壁破壊後、透過壁越しに敵が見える場面、扉の箇所の案）、場所名の一覧と読み

## 不明なら止めて聞く
- ゲームのタイル寸法と素材の16pxが合わない場合
- 壁の正面のはみ出しでキャラが隠れる・判定と見た目のずれが目立つ場合
- 静的な層にまとめると視界マスク等の既存描画に大きな改修が要る場合
- 間取り変更で大将の候補部屋・Bot・コバコの仕様を変えないと動かない場合
