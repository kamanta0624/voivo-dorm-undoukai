## 1. ビィの技（現行の技名定義のまま。改名しない）: 予約された相手に爆発までのカウントダウン
- 現状: src/server/skills/bii.ts。触れた敵を予約（e.marks）→ 終了時ポーズ → ポーズ終わりにダメージ。予約の目印は e.v で両陣営に送っている
- 変更: 予約された相手の頭上に「爆弾マーク＋爆発までの残り秒数」を表示。0 になった瞬間にダメージ（既存のポーズ終わりのダメージと一致させる）
  - 残り秒数 = 技の残り時間 + ポーズ時間（予約された時点から数え始める）。表示は切り上げの整数
  - サーバーは爆発予定時刻（技の終了時刻＋pose）を e.v に含める。オーバー中に予約がなければポーズしない既存仕様はそのまま
  - ビィが途中で倒されて不発になったら表示も消す。予約後に倒れた相手（marked() で外れる相手）の表示も消す
  - 両陣営に見える（既存の目印と同じ扱い）
- 成功基準: 予約された敵にマークと数字が出て、数字が 0 になるのと同時にダメージ。不発時・相手撃破時は表示が消える。verify に1項目追加

## 3. あいえるたんの加速範囲の位置ずれ: 調査のみ
- 症状: 技を使うと、加速範囲（発動エフェクトの輪）が、クライアントで見えている自キャラの位置より少し前に出るように見える
- 現状: server/skills/ierutan.ts が発動時のサーバー位置で範囲判定し、room.addFx(p, 'aura', ...) でその位置にエフェクトを出す。クライアントの自キャラは予測（this.pred.render）で描いている（client/main.ts 1041 行付近）
- 調べること:
  1. エフェクトの位置と、その瞬間のクライアントの自キャラの描画位置のずれ（量・向き。移動中／静止中）
  2. 見た目だけのずれか、範囲判定（味方に加速が付くかどうか）もずれているか
  3. 原因（入力の遅延・予測とサーバー位置の差・エフェクトの座標の扱い など）
  4. 同じ作りの他の技（自分中心の addFx を使うもの: ビィの残像、リコール跡、回復など）にも同じずれがあるか
- 修正はしない。原因と修正案（複数あれば利点・欠点）を報告し、本人の判断を待つ
- 成功基準: 再現手順と、ずれの計測値、原因の特定根拠を報告
