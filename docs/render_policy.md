# 描画の指針（クライアントの負荷を増やさないための決まり）

2026-11-24 制定。スマホ（iPhone 15 Pro・PWA）の発熱調査（perf1〜perf3）で分かったことから。新しい描画・演出・UI を作る時、既存を直す時はこれに従う。守れない場合は理由を引き継ぎ書の報告に書く。

1. GPU に置いた画像は使い回す。描き直して GPU へ送り直すのは、変わった所だけ・最小の範囲だけ。Phaser の CanvasTexture.refresh() は全量転送なので、大きな canvas に対して試合中に呼ばない（初回・リセット時だけ）
2. 同時に使うテクスチャの枚数を増やしすぎない。Phaser が1回の描画でまとめられるのは16枚まで。小さな画像は1枚にまとめる（テクスチャアトラス）。画面外の大きな画像は描かない（visible=false 等）
3. 線・図形（Phaser の Graphics）を毎フレーム描き直さない。変わらない形は起動時に画像（テクスチャ）にして、Image・Sprite・Blitter で置く。毎フレーム描くのは本当に毎フレーム形が変わる物だけ
4. 画面外の物は描かない・更新しない（カメラの表示範囲で間引く）
5. DOM（HUD・ボタン・文字）は値が変わった時だけ書き換える。要素の参照は一度だけ取る（毎フレーム querySelector しない）。毎フレーム変わる要素に filter・box-shadow・blur・conic-gradient の更新を掛けない
6. 毎フレームの配列・文字列の作り直し（座標のコピー、SVG 文字列の組み立てなど）は、必要な時（表示中・入力が変わった時）だけにする
7. 反映の前に verify/perfgate.ts（Chromium と WebKit、スマホの画面）に合格する。tools/deploy.sh の関門で自動で流れ、不合格なら反映されない。合否は「不要な DOM の書き換え」の4つの定義：同じ値の書き込み0回／強制レイアウト0回（DOM を書いた後に位置・大きさを読まない）／レイアウトを起こす書き込み（文字・クラス・innerHTML・transform と opacity 以外の style）は1要素あたり毎秒 N 回まで（N は verify/perf_budget.json）／毎フレーム動かす物は transform・opacity だけ。WebGL の drawcall・転送量・層の数は perf_budget.json の上限（参考値）
8. 繰り返しの動き（回転・点滅・脈動・歩くコマ・光る）は、JS から毎フレーム書かず、CSS の animation で transform・opacity だけを動かす。色・枠・影・filter・conic-gradient の角度・画像の src を動かしたい時は、それぞれの状態を重ねた層にして opacity で切り替える。動きを頭から始め直す時は、同じ中身の動きを2つ用意して名前を交互にする（クラスを外して offsetWidth を読む書き方はしない）
9. 位置・大きさは、書いた後に読まない。読むのは ResizeObserver の中（レイアウトが済んだ後）か、そのフレームで何も書く前。測った値は覚えて使い回す。クラスの付け外しも、値が変わる時だけ（classList.toggle は同じ値でも書き込みになる）

## 過去の事故（同じ書き方をしない）
- perf1（2026-11-24）：視界の壁判定が、1フレームに数万回の Set 引きになっていた（maptile3）。また壁が壊れるたびにマップ全体（3104×2016）を GPU へ送り直していた。直し方：壁判定を事前に計算した格子にする、マップを区画のテクスチャに分けて掛かる区画だけ送る。見つけ方：?perf=1 の ray 時間と、WebGL の転送量
- perf2〜3（2026-11-24）：区画に分けたことで drawcall が増えた。また視界ポリゴンの頂点のコピーと SVG の組み立てを毎フレームしていた。直し方：マップを1枚に戻して壊れた矩形だけを texSubImage2D で送る、頂点と SVG は変わった時だけ作る
- perf4（2026-11-25）：Graphics の毎フレームの描き直し、出撃ボタンの光（box-shadow のアニメーション）、毎フレーム変わる HUD が #fx 全体の描き直しを起こしていた。直し方：変わらない形は画像にする、光は2枚の層の opacity の入れ替え、毎フレーム変わる部品は独立した層に。見つけ方：Chrome のトレース（Paint・Raster）
- perf5（2026-11-25）：試合中、1フレームに約1回のスタイル再計算・レイアウトが起きていた（ゲージ・HP バーの width、ラベルの left/top、リールの書き換え）。直し方：長さ・位置は transform、リールは変わった所だけ書く。見つけ方：CDP の RecalcStyleCount・LayoutCount
- perf6（2026-11-28）：Phaser が覚えるキャンバスの位置が、自前で合わせた位置とずれていて、0.5秒ごとの resize → 測り直し → 強制レイアウトが毎フレーム続いていた（screen1 から）。加えて、リーチの歩くドットの left と src、全回転の虹の角度（@property の conic-gradient）を毎フレーム書いていた。直し方：合わせた後に scale.updateBounds()、ドットは transform、虹は正方形を transform で回す。見つけ方：書き込みを要素ごとに数える計測（今の perfgate の元）と、強制レイアウトの読み取り元の関数
- dom1（2026-11-28）：perf6 の後も、同じ値のクラスの付け外し（毎フレーム）、書いた後の位置の読み取り（キルログ域・左上の一覧・余白の立ち絵）、技のクールタイムの扇形（conic-gradient の角度を毎フレーム）、リーチの枠の点滅（border-color・box-shadow）、先バレの光（offsetWidth の読み直し）、灰色になるカットイン・出撃ボタンの明るさ（filter）が残っていた。直し方：上の 8・9。見つけ方：perfgate の4つの定義。再発防止として tools/deploy.sh に関門を置いた
